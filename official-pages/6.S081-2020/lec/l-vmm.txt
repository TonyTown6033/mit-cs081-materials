*** 虚拟机

什么是虚拟机？
  计算机模拟，精确到足以运行操作系统

图表：硬件、主机/VMM、来宾内核、来宾进程
  VMM 可能是独立的，或者
  VMM 可能在主机操作系统中运行，例如Linux

为什么要使用虚拟机？
  每台物理机运行大量访客
    个别服务通常需要适度的资源
    会浪费大部分专用服务器
    用于云和企业计算
    需要在现有操作系统内核下建立一个新层来管理多个来宾
  虚拟机比进程提供更好的隔离
  一台计算机，多个操作系统（OSX 和 Windows）
  内核开发环境（如qemu）
  技巧：检查点、迁移、监控

虚拟机有着悠久的历史
  20 世纪 60 年代：IBM 使用虚拟机共享大型机器
  20 世纪 90 年代：VMWare 重新普及适用于 x86 硬件的虚拟机
  2000年代：广泛应用于云、企业

我们为什么谈论虚拟机？
  操作系统设计中一些最有趣的动作已经转移到虚拟机上
    与传统操作系统内核有很多重叠
    还有一些新的挑战/机遇
  通过在操作系统下插入一个新层可以更轻松地解决一些问题
  虚拟机同时影响操作系统（上图）和硬件（下图）

VM 必须有多准确？
  通常的目标：
    来宾不知道它正在虚拟机中运行
    主机可以支持任何来宾操作系统
  所以我们想要：
    访客无法区分虚拟机和真实计算机
    来宾不可能逃脱其虚拟机
  必须允许标准操作系统启动、运行
  必须包含恶意软件
    不能让guest脱离虚拟机！
  在实践中，许多虚拟机妥协
    来宾操作系统知道它正在虚拟机上运行，
    为了提高效率进行了修改

我们可以通过编写软件来模拟机器指令来构建虚拟机
  VMM 解释每条访客指令
  维护来宾虚拟机状态
    32 个寄存器、satp、模式、RAM、磁盘等
  专业人士：很明显这是可能的
  缺点：慢

想法：在真正的 CPU 上执行客户指令——快！
  如果来宾内核执行特权指令怎么办？
    例如guest 将新页表加载到 satp 中
    无法让客户内核直接访问管理寄存器&c！

想法：在用户模式下运行来宾内核
  类似于将来宾内核作为 xv6 进程运行
  当然，来宾内核假设它处于监督模式
  普通指令工作正常
    添加两个寄存器、函数调用等
  特权 RISC-V 指令在用户模式下是非法的
    会导致 VMM 陷入陷阱
  VMM 陷阱处理程序模拟特权指令
    可能将特权操作应用于虚拟状态
      例如读/写sepc
    或许可以改造并应用到真实的硬件上
      例如分配给卫星技术方案
  “陷阱与模仿”
  不错，你可以完全用软件构建这样的虚拟机
    您可以将 xv6 修改为 RISC-V 的陷阱和模拟 VMM

捕获并模拟 VMM 必须“虚拟化”哪些 RISC-V 状态？
  不允许 b/c 来宾查看/更改真实机器状态。
  所有 s* 寄存器（sepc、stvec、scause、satp 和 c）
  模式
  哈特数

RISC-V 非常好用。陷阱和模拟虚拟化
  如果您尝试在用户模式下执行所有特权指令，则会陷入困境
  并非所有 CPU 都那么好——例如 32 位 x86
    一些特权指令不会陷入；如果在用户模式下运行，x86 会忽略

对于 RISC-V 陷阱和仿真，在以下情况下会发生什么：

...来宾内核执行sret（返回给用户）？
    [图：VMM、来宾内核、来宾用户、虚拟状态、真实硬件状态]
    CPU 陷入 VMM
      这确实是从用户模式到管理模式的一个陷阱
      访客的 PC 保存在 epc 中（也许还有 trapframe）
    VMM 陷阱处理程序：
      虚拟模式=用户
      真实sepc = 虚拟sepc
      [为PTE_U切换页表]
      从陷阱返回

...来宾用户代码执行 ecall 来进行系统调用？
    CPU 陷阱进入 VMM（ecall 总是生成陷阱）
    VMM 陷阱处理程序：
      虚拟sepc = 真实sepc
      虚拟模式=主管
      虚拟原因=“系统调用”
      真实 sepc = 虚拟 stvec
      [为PTE_U切换页表]
      从陷阱返回

...来宾内核读取原因，例如csrr a0，原因
    陷入VMM
    trapframe a0 = 虚拟原因
    实数sepc += 4
    从陷阱返回

...来宾内核写入 satp？
  VMM必须确保guest只访问自己的内存
    并且必须重新映射来宾物理地址
  访客页表：
    guest va -> guest pa
  该客人的 vmm 地图
    guest pa -> host pa
  VMM 的“影子”页表
    guest va -> host pa
  VMM在真实satp中安装影子页表

...来宾内核修改活动页表中的 PTE？
  VMM 无需执行任何操作
  RISC-V 规范表示 PTE 修改要到 sfence.vma 才会生效
  sfence.vma 导致 VMM 陷入陷阱
    VMM生成新的影子页表

如何模拟设备？
  例如磁盘、网卡、显示器
  一个很大的挑战！
  策略：模拟常见的现有真实设备
    需要运行不经意的来宾操作系统
    拦截内存映射控制寄存器读/写
      通过将这些页面标记为无效，因此 VMM 会出现页面错误
    VMM 将页面错误转换为（不同）真实设备上的操作
    例如qemu 模拟 xv6 的 uart/console
      qemu 将 uart r/w 转换为显示或 ssh 的字符
  策略：为提高效率而定制的特殊虚拟设备
    需要来宾操作系统驱动程序——即来宾知道它在虚拟机中
    比控制寄存器 r/w 上的捕获更加简化
    例如xv6的virtio_disk.c； qemu 在文件 fs.img 上变成 r/w
  策略：直通访问真实硬件设备
    来宾操作系统可以直接访问设备硬件，没有陷阱
    通常需要设备的特定支持
      现代 NIC 已支持
    可以非常高效

陷阱和模拟效果很好——但可能很慢！
  VMM中有很多陷阱

*** 硬件支持的 x86 虚拟化

VT-x/VMX/SVM：硬件支持的虚拟化
  Intel（和 AMD）CPU 具有硬件虚拟化支持
    CPU直接支持虚拟与真实状态
    因此来宾可以执行特权指令而不被捕获
  比捕获和模拟更快
  更容易实现 VMM 软件
  广泛用于实现虚拟机

VT-x root 和非 root 模式
  【图：两组寄存器，加上EPT】
  主机（VMM）以“根模式”运行——没什么特别的
  来宾以“非 root 模式”运行
    具有全套“虚拟”控制寄存器
      satp、stvec、用户与主管等的 x86 等效项
    来宾管理模式可以完成操作系统内核期望的一切
      切换到（来宾）用户模式，进行系统调用、陷阱等
    非root模式*看起来*就像普通计算机一样
    但 VT-x 非 root 模式在一些关键方面限制了 guest 虚拟机
      主要是通过页表，我们稍后会看到
  在 root/非 root 模式之间切换的新说明
    VMLAUNCH/VMRESUME: root -> non-root
    VMCALL: non-root -> root
  设备中断（例如定时器、磁盘）导致退出非 root 模式
    VMM 默认处理设备
  虚拟机控制结构（VMCS）
    非root模式退出时虚拟状态保存在VMCS中
    在 VMLAUNCH/VMRESUME 中从 VMCS 恢复虚拟状态

VT-x 页表
  problem:
    我们想让客户内核控制页表，
    我们希望将来宾限制为其允许的物理内存，
    但我们不希望在以下情况下陷入 VMM 中：
      the guest sets %cr3 (== satp) or modifies a PTE.
  EPT：VT-x 在非根模式下有“两层”地址转换
    VMM建立EPT页表
    仅包含访客可以使用的“访客物理地址”
    映射到 VMM 为 guest 分配的真实（主机）物理地址
    EPT = 扩展页表
  MMU 硬件参考 %cr3 来获取访客 pa，
    然后使用EPT将guest pa转换为host pa
  EPT 对访客不可见
  so:
    来宾可以自由读取/写入 %cr3、更改 PTE、读取 D 位等
    VMM 仍然可以通过 EPT 提供隔离
  典型设置：
    VMM 分配一些 RAM 供 guest 使用
    VMM 将客户物理地址 0..size 映射到 EPT 中的 RAM
    guest 使用 %cr3 配置 guest 进程地址空间

*** 沙丘

大创意：
  使用 VT-x 运行 Linux 用户进程（而不是运行来宾内核）
  然后用户代码可以快速直接访问页表、异常等
  允许用户代码有效地：
    沙箱不可信代码
    修改页表并采取页面错误

该计划
  [图]
  Dune 是 Linux 的“可加载内核模块”
  普通进程可以切换到“沙丘模式”
  沙丘模式过程仍然是一个过程
    有内存，可以进行Linux系统调用（通过VMCALL）
  隔离机械有点不同
    VT-x 非根管理员模式
    通过 EPT 页表进行内存保护
    定时器中断进入Linux，而不是进程，因此Linux控制调度
  Dune 为流程提供了附加功能
    读写自己的页表，包括PTE D（脏）位
      比 Linux mprotect() 系统调用更快
    处理自己的页面错误
      比让 Linux 将故障转化为上行调用更快
    切换到（访客）用户模式
    拦截来宾用户系统调用和页面错误

示例：沙盒执行（论文第 5.1 节）
  假设您的网络浏览器想要运行第三方插件
    例如视频解码器或广告拦截器
    该插件可能是恶意的或有错误的
  浏览器需要“沙箱”
    执行插件，但限制系统调用/内存访问
  假设浏览器作为 Dune 进程运行：
    [图：访客管理员模式下的浏览器、插件访客用户模式]
    使用 PTE_U 映射创建页表供内存插件使用
      以及浏览器内存其余部分的非 PTE_U 映射
    设置%cr3
    在访客用户模式下进入不受信任的代码
    插件可以通过页表读取/写入图像内存
    插件可以执行系统调用指令
      但它的系统调用陷入浏览器（而不是底层内核）
      并且浏览器可以决定是否允许每一个

示例：垃圾收集 (GC)
  （修改后的 Boehm 并发标记和清除收集器）
  GC 按照指针查找所有活动（可到达）对象
    从寄存器开始
  但是这个 GC 是并发的——所以程序可能会在 GC 跟踪到对象后修改它
  GC 需要一种方法来知道哪些对象被修改，
    所以它可以重新访问修改过的对象
  沙丘有什么帮助？
    使用PTE脏位（PTE_D）检测写入页
    GC 完成后清除所有脏位
    Dune 允许直接访问 PTE
      比通过 Linux 系统调用获取 PTE 快得多
