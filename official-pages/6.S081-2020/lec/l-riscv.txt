C 代码被编译为机器指令。

RISC-V 抽象机器
  没有类似 C 的控制流，没有变量、类型等概念……
  基础 ISA：程序计数器，32 个通用寄存器（x0--x31）

reg    | name  | saver  | description
-------+-------+--------+------------
x0     | zero  |        | hardwired zero
x1     | ra    | caller | return address
x2     | sp    | callee | stack pointer
x3     | gp    |        | global pointer
x4     | tp    |        | thread pointer
x5-7   | t0-2  | caller | temporary registers
x8     | s0/fp | callee | saved register / frame pointer
x9     | s1    | callee | saved register
x10-11 | a0-1  | caller | function arguments / return values
x12-17 | a2-7  | caller | function arguments
x18-27 | s2-11 | callee | saved registers
x28-31 | t3-6  | caller | temporary registers
pc     |       |        | program counter

运行示例：sum_to(n)

  int sum_to(int n) {
    int acc = 0;
    for (int i = 0; i <= n; i++) {
      acc += i;
    }
    return acc;
  }

这段代码在汇编中是什么样的？

  # sum_to(n)
  # expects argument in a0
  # returns result in a0
  sum_to:
    mv t0, a0          # t0 <- a0
    li a0, 0           # a0 <- 0
  loop:
    add a0, a0, t0     # a0 <- a0 + t0
    addi t0, t0, -1    # t0 <- t0 - 1
    bnez t0, loop      # 若 t0 != 0：pc <- loop
    ret

有限的抽象
  没有类型化的位置参数
  没有局部变量
  只有寄存器

机器甚至看不到汇编代码
  只看到机器指令的二进制编码
    每条指令：16 位或 32 位
  例如，`mv t0, a0` 被编码为 0x82aa
  并非与汇编严格一一对应，但十分接近

另一个函数如何调用 sum_to？

  main:
    li a0, 10          # a0 <- 10
    call sum_to

call 的语义是什么？

  call label :=
    ra <- pc + 4       ; ra <- 下一条指令的地址
    pc <- label        ; 跳转到 label

机器不理解标签
  将被转换为相对 pc 的跳转或绝对跳转

return 的语义是什么？

  ret :=
    pc <- ra

如果我们希望一个函数调用另一个函数，该怎么做？

  # sum_then_double(n)
  # 参数通过 a0 传入
  # 返回值存放在 a0 中
  sum_then_double:
    call sum_to
    li t0, 2           # t0 <- 2
    mul a0, a0, t0     # a0 <- a0 * t0
    ret

  main:
    li a0, 10
    call sum_then_double

让我们来试一试：demo2.S
  程序陷入了无限循环
  原因：返回地址（ra）被覆盖了

如何修复：将 ra 保存到某个地方
  保存到另一个寄存器？行不通，只是把问题推后了。
  解决方案：保存到栈上

  sum_then_double:
    addi sp, sp, 16    # 函数序言：
    sd ra, 0(sp)       # 在栈上开辟空间，保存寄存器
    call sum_to
    li t0, 2
    mul a0, a0, t0
    ld ra, 0(sp)       # 函数尾声：
    addi sp, sp, -16   # 恢复寄存器，恢复栈指针
    ret

到目前为止，我们的函数之间相互配合
  这之所以有效，是因为我们编写了所有相关代码
  也可以用任何其他方式来实现
    例如：通过 t2 传递参数，通过 t3 获取返回值

围绕此问题的约定称为"调用约定"
  参数如何传递？
    a0, a1, ..., a7，其余参数压入栈中
  返回值如何传递？
    a0, a1
  谁来保存寄存器？
    指定为调用者保存或被调用者保存
    ra 可以是被调用者保存的寄存器吗？
  我们的汇编代码应遵循此约定
  GCC 生成的 C 代码遵循此约定
  这意味着所有人的代码都可以互操作，包括 C/asm 互操作
  阅读：demo4.c / demo4.asm
    可以看到函数的序言、主体和尾声
    为什么不保存 ra？叶函数，无需保存
    s0/fp 是怎么回事？
      我们使用了 -fno-omit-frame-pointer 编译

栈
                   .
                   .
      +->          .
      |   +-----------------+   |
      |   | return address  |   |
      |   |   previous fp ------+
      |   | saved registers |
      |   | local variables |
      |   |       ...       | <-+
      |   +-----------------+   |
      |   | return address  |   |
      +------ previous fp   |   |
          | saved registers |   |
          | local variables |   |
      +-> |       ...       |   |
      |   +-----------------+   |
      |   | return address  |   |
      |   |   previous fp ------+
      |   | saved registers |
      |   | local variables |
      |   |       ...       | <-+
      |   +-----------------+   |
      |   | return address  |   |
      +------ previous fp   |   |
          | saved registers |   |
          | local variables |   |
  $fp --> |       ...       |   |
          +-----------------+   |
          | return address  |   |
          |   previous fp ------+
          | saved registers |
  $sp --> | local variables |
          +-----------------+

调试
  examine：检查内存内容
    x/nfu addr
      n：计数
      f：格式
      u：单元大小
  step/next/finish
    step：执行下一行 C 代码
    next：执行下一行 C 代码，跳过函数调用
    finish：继续执行直到当前函数调用结束
  stepi/nexti
    stepi：执行下一条汇编指令
    nexti：执行下一条汇编指令，跳过函数调用
  layout next
    切换布局视图
  条件断点
    仅在满足某条件时中断（例如某变量具有特定值）
  观察点
    当某内存地址的值发生变化时中断
