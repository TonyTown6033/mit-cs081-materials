6.828 2016年第8讲：页面错误
==

* 计划：你可以用虚拟机做一些很酷的事情
  - 更好的性能/效率
    例如，一页由零填充
    例如，写时复制分叉
  - 新功能
    例如，内存映射文件
  
* 虚拟内存：几种视图
  * 主要目的：隔离
    每个进程都有自己的地址空间
  * 虚拟内存提供间接级别
    为内核提供了做很酷的事情的机会
	已经有一些例子：
	- 共享蹦床页面
	- 保护页面
	但更有可能...
	
* 关键思想：在缺页时更改页表
  页面错误是陷阱的一种形式（类似于系统调用）
  xv6 因页面错误而发生恐慌
    但您不必惊慌！
  Instead:
    更新页表而不是恐慌
	重新启动指令（请参阅陷阱讲座中的 userret()）
  页面错误和更新页表的结合是强大的！
	
* RISC-V 页面错误
  16 个异常中有 3 个与分页相关
  异常导致受控传输到内核
    参见陷阱讲座
	
* 我们在页面错误时可能需要的信息来做一些有趣的事情：
  1）引起故障的虚拟地址
    参见 stval 寄存器；页面错误将其设置为错误地址
  2) 导致故障的违规类型
    查看原因寄存器值（指令、加载和存储页面错误）
  3）发生故障的指令及方式
    User IP: tf->epc
    U/K 模式：隐含在 usertrap/kerneltrap 中
  
* 惰性/按需页面分配
  * sbrk() 是老式的；
    应用程序经常请求它们需要的内存
    - 例如，分配最大可能的输入，但是
      应用程序通常会使用较少的
    如果他们要求太多， sbrk() 可能会很昂贵
    - 例如，如果所有内存都在使用中，则必须等到
      内核已驱逐一些页面以释放内存
    sbrk 分配可能永远不会使用的内存。
  * 现代操作系统延迟分配内存
    plan:
      当应用程序需要时分配物理内存
      adjust p->sz on sbrk, but don't allocate
      当应用程序使用该内存时，将导致页面错误
      在页面错误时分配内存
      恢复故障指令
    可能使用更少的内存
      如果没有使用，没有故障，不分配
    将分配成本分散到页面错误上
    sbrk() 中的前期
  * 演示
    修改sysproc.c
    修改trap.c
    修改vm.c

* 一页填零（按需填零）
  * 应用程序通常有很大一部分内存必须为零
    全局数组等
    “块起始符号”(bbs) 段
  * 因此，内核必须经常用零填充页面
  *想法：memset*一页*带零
    当内核需要零填充页面时映射该页面写时复制
    写入时复制页面并将其映射到应用程序地址空间中读/写

* 写时复制分叉
  *观察：
    xv6 fork 从父级复制所有页面（请参阅 fork()）
    但 fork 后面通常紧接着 exec
  * 想法：父子之间共享地址空间
    修改 fork() 以映射页面写时复制
      在 PTE 中使用额外的可用系统位 (RSW)
    出现页面错误时，复制页面并将其映射为读/写

* 请求分页
  * 观察：exec 将完整文件加载到内存中（参见 exec.c）
    昂贵：需要时间（例如，文件存储在慢速磁盘上）
    不必要的：也许不会使用整个文件
  * 思路：按需从文件加载页面
    分配页表条目，但按需标记它们
    发生故障时，从文件中读取页面并更新页表条目
    需要保留一些有关页面在磁盘上位置的元信息
      该信息通常位于称为虚拟内存区域 (VMA) 的结构中
  * 挑战：文件大于物理内存（参见下一个想法）

* 使用大于物理内存的虚拟内存
  * 观察：应用程序可能需要比物理内存更多的内存
  * 想法：将地址空间中不常用的部分存储在磁盘上
    透明地对地址空间进行页入和页出页
  * 当工作集适合物理内存时才起作用
    最流行的替换策略：最近最少使用（LRU）
    PTE 中的 A(cess) 位帮助内核实现 LRU
  * 演示：运行top和vmstat
    在笔记本电脑上和 dialup.athena.mit.edu
    参见 VIRT RES MEM SHR 列
  
* 内存映射文件
  * 想法：允许使用加载和存储来访问文件
    可以轻松读取和写入文件的一部分
    例如，不必使用 lseek 系统调用更改偏移量
  * Unix 系统对 m 映射文件的新系统调用：
    void *mmap(void *addr, size_t 长度, int prot, int flags, int fd, off_t offset);
  * 内核按需调入文件页面
    当内存已满时，调出文件中不经常使用的页面

* 共享虚拟内存
  * 思路：让不同机器上的进程共享虚拟内存
    给人一种跨网络物理共享内存的错觉
  * 复制只读页面
  * 写入时使副本无效
  
* TLB管理
  CPU 缓存分页转换以提高速度
  xv6 在用户/内核转换期间刷新整个 TLB
    why?
  RISC-V 允许更复杂的计划
    * PTE_G：全局TLB位
      什么页面可以使用这个？
    * ASID 号码
      TLB 条目标有 ASID，因此内核可以有选择地刷新
      SATP 采用 ASID 编号
      sfence.vma 还采用 ASID 编号
    * 大页面
      2MB 和 1GB
