为什么文件系统有用？
  重启后的持久性
  命名和组织
  在程序和用户之间共享

为什么有趣？
  崩溃恢复
  performance/concurrency
  分享
  安全
  抽象很有用：管道、设备、/proc、/afs、Plan 9
    因此面向 FS 的应用程序可以处理多种对象
  两个实验室的主题

API 示例——UNIX/Posix/Linux/xv6/&c：
  fd = open("x/y", -);
  写（fd，“abc”，3）；
  链接（“x/y”，“x/z”）；
  取消链接（“x/y”）；
  写（fd，“def”，3）；
  关闭（fd）；
  // file y/z contains abcdef
  
UNIX FS API 中可见的高级选择
  对象：文件（相对于虚拟磁盘、数据库）
  内容：字节数组（与 80 字节记录、BTree 相比）
  命名：人类可读（相对于对象 ID）
  组织：名称层次结构
  同步：无（与锁定、版本相比）
    link()/unlink() 可以与 open() 同时更改名称层次结构
  还有其他文件系统 API，有时差异很大！

API 的一些含义：
  fd 指的是某物
    即使文件名更改也会保留
    或者如果文件在打开时被删除！
  一个文件可以有多个链接
    即出现在多个目录中
    这些事件没有一件是特别的
    so 文件必须将信息存储在目录以外的位置
  thus:
    FS 将文件信息记录在磁盘上的“inode”中
    FS 指带有 i-number 的 inode（FD 的内部版本）
    inode 必须有链接计数（告诉我们何时释放）
    inode 必须有打开 FD 的计数
    inode 释放推迟到最后一个链接和 FD 消失为止

存储在持久介质上的数据
  数据在没有电源的情况下保留在磁盘上
  常用存储介质：
    硬盘驱动器（大但慢，便宜）
    固态硬盘（更小，但速度更快，而且更昂贵）
  历史上，磁盘通常以 512 字节为单位进行读/写，称为扇区

硬盘驱动器 (HDD)
  同心轨道
  每个磁道都是一系列扇区
  磁头必须寻道，磁盘必须旋转
    随机访问速度慢（每次访问 5 或 10 毫秒）
    顺序访问速度更快（100 MB/秒）
  每个扇区的 ECC
  只能读/写整个扇区
  因此：子扇区写入成本高昂（读取-修改-写入）

固态硬盘 (SSD)
  非易失性“闪存”存储器
  随机访问：100微秒
  顺序：500 MB/秒
  内部复杂——除了有时表现之外是隐藏的
    闪存在重写之前必须被擦除
    限制闪存块可写入的次数
    SSD 应对一定程度的间接性——重新映射的块

对于 HDD 和 SSD：
  顺序访问比随机访问快得多
  大读/写比小读/写快
  这些都会影响 FS 的设计和性能
  
磁盘块
  大多数操作系统使用多个扇区的块，例如4 KB 块 = 8 个扇区
  减少簿记并寻求间接费用
  xv6 使用 2 扇区块

磁盘布局
  xv6 将磁盘视为扇区数组（忽略磁盘的物理属性）
  0：未使用
  1：超级块（大小，ninodes）
  2：交易日志
  32：inode 数组，打包成块
  45：块正在使用的位图（0=空闲，1=已使用）
  46：文件/目录内容块
  磁盘末尾

例如，如果并发调用 alloc 怎么办？
   他们会得到相同的索引节点吗？
   在 ialloc 中注意 bread / write / brelse
   bread 锁定块，也许等待，然后从磁盘读取
   brelse解锁区块

我们看一下bio.c中的块缓存
   块缓存仅保存一些最近使用的块
   bcache 位于 bio.c 的开头

FS 调用 bread，bread 调用 bget
   bget 查看块是否已缓存
   如果存在，锁定（可能等待）并返回块
     可能会在睡眠锁中等待，直到当前使用的进程释放
     睡眠锁定使呼叫者进入睡眠状态（如果已锁定）
   如果不存在，则重新使用现有的缓冲区
   b->refcnt++ prevents buf from being recycled while we're waiting
   不变式：内存中磁盘块的一份副本

这里有两个级别的锁定
  bcache.lock 保护缓存中内容的描述
  b->lock protects just the one buffer

  遍历当时的一个路径名元素
  可能涉及许多块：

    如果一个进程在磁盘上阻塞，另一进程可能会继续查找

让我们看看 namex() (kernel/fs.c)
  ilock()：锁定当前目录
  查找下一个目录 inode
  然后解锁当前目录
  另一个进程可能会取消链接下一个 inode
    但 inode 不会被删除，因为 inode 的 refcnt > 0
  风险：下一个指向与当前相同的索引节点（查找“.”）
    在锁定下一个之前解锁当前
