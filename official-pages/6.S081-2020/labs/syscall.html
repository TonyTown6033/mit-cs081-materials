系统调用追踪

在此作业中，您将添加系统调用跟踪功能，该功能可以在调试后续实验时为您提供帮助。您将创建一个新的 trace 将控制跟踪的系统调用。它应该采用一个参数，一个整数“掩码”，其位指定要跟踪哪些系统调用。例如，为了跟踪 fork 系统调用，程序调用 trace(1 << SYS_fork), 其中 SYS_fork 是来自的系统调用号 kernel/syscall.h。如果掩码中设置了系统调用的编号，则必须修改 xv6 内核，以便在每个系统调用即将返回时打印一行。该行应包含进程 ID、系统调用名称和返回值；您不需要打印系统调用参数。的 trace 系统调用应该启用对调用它的进程及其随后派生的任何子进程的跟踪，但不应影响其他进程。

我们提供一个 trace 运行另一个启用跟踪的程序的用户级程序（请参阅 user/trace.c）。完成后，您应该看到如下输出：

在上面的第一个示例中，trace 仅调用 read 系统调用 grep 跟踪。 32 是 1<<SYS_read。在第二个示例中，trace 在跟踪所有系统调用的同时运行 grep； 2147583647 已设置所有 31 个低位。在第三个示例中，未跟踪程序，因此不会打印跟踪输出。在第四个示例中，fork 系统调用了所有后代 forkforkfork 测试在 usertests 正在被追踪。如果您的程序的行为如上所示（尽管进程 ID 可能不同），则您的解决方案是正确的。

一些提示：

  • 添加 $U/_trace 到 Makefile 中的 UPROGS

  • 运行 make qemu 你会看到编译器无法编译 user/trace.c，因为系统调用的用户空间存根尚不存在：将系统调用的原型添加到 user/user.h，一个存根 user/usys.pl，以及一个系统调用号 kernel/syscall.h。 Makefile 调用 perl 脚本 user/usys.pl，这会产生 user/usys.S，实际的系统调用存根，使用 RISC-V ecall 指令转换到内核。解决编译问题后，运行 trace 32 grep hello README;它会失败，因为你还没有在内核中实现系统调用。

  • 添加一个 sys_trace() 函数于 kernel/sysproc.c 通过在新变量中记住其参数来实现新的系统调用 proc 结构（见 kernel/proc.h）。从用户空间检索系统调用参数的函数位于 kernel/syscall.c，您可以在中查看它们的使用示例 kernel/sysproc.c.

  • 修改 fork() （见 kernel/proc.c) 将跟踪掩码从父进程复制到子进程。

  • 修改 syscall() 函数于 kernel/syscall.c 打印跟踪输出。您将需要添加要索引的系统调用名称数组。

系统信息

在此作业中，您将添加一个系统调用， sysinfo，收集有关正在运行的系统的信息。系统调用需要一个参数：一个指向 struct sysinfo （见 kernel/sysinfo.h）。内核应该填写这个结构体的字段： freemem 字段应设置为可用内存的字节数，并且 nproc 字段应设置为其进程的数量 state 不是 UNUSED。我们提供测试程序 sysinfotest;如果打印出“sysinfotest: OK”，则说明您通过了此作业。

一些提示：

  • 添加 $U/_sysinfotest 到 Makefile 中的 UPROGS

  • 运行 make qemu; user/sysinfotest.c 将无法编译。添加系统调用 sysinfo，遵循与之前作业相同的步骤。声明 sysinfo() 的原型 in user/user.h 你需要预先声明的存在 struct sysinfo: 

        struct sysinfo;
    int sysinfo(struct sysinfo *);
    解决编译问题后，运行 sysinfotest;它会失败，因为你还没有在内核中实现系统调用。

  • sysinfo 需要复制一个 struct sysinfo 回到用户空间；看到 sys_fstat() (kernel/sysfile.c）和 filestat() (kernel/file.c）了解如何使用的示例 copyout().

  • 要收集可用内存量，请添加一个函数 kernel/kalloc.c

  • 要收集进程数，请添加一个函数 kernel/proc.c
