实验：文件系统

在本实验中，你将为 xv6 文件系统添加大文件和符号链接支持。

在编写代码之前，你应该阅读 xv6 书 并研究相应的代码。

获取本实验的 xv6 源代码并切换到 util branch: 

  $ git fetch
  $ git checkout fs
  $ make clean

大文件

在本作业中，你将增大 xv6 文件的最大大小。目前，xv6 文件被限制为 268 个块，即 268*BSIZE 字节（在 xv6 中 BSIZE 为 1024）。这一限制源于 xv6 的 inode 包含 12 个"直接"块号和一个"一级间接"块号，后者指向一个最多可存储 256 个块号的块，共计 12+256=268 个块。

该 bigfile 命令会创建尽可能长的文件，并报告该文件的大小： 

$ bigfile
..
wrote 268 blocks
bigfile: file is too small
$
测试失败是因为 bigfile 期望能够创建一个包含 65803 个块的文件，但未经修改的 xv6 将文件限制为 268 个块。

你将修改 xv6 文件系统代码，以在每个 inode 中支持一个"二级间接"块，该块包含 256 个一级间接块的地址，每个一级间接块最多可包含 256 个数据块的地址。最终，一个文件将能够由最多 65803 个块组成，即 256*256+256+11 个块（之所以是 11 而非 12，是因为我们将牺牲一个直接块编号来存放二级间接块）。

准备工作

该 mkfs 程序创建 xv6 文件系统磁盘镜像，并决定文件系统的总块数；该大小由 FSSIZE 中 kernel/param.h控制。你会看到 FSSIZE 在本实验的代码仓库中被设置为 200,000 个块。你应该在 make 的输出中看到来自 mkfs/mkfs 的如下输出： 
nmeta 70 (boot, super, log blocks 30 inode blocks 13, bitmap blocks 25) blocks 199930 total 200000
这一行描述了 mkfs/mkfs 构建的文件系统：它包含 70 个元数据块（用于描述文件系统的块）和 199,930 个数据块，共计 200,000 个块。
如果在实验过程中的任何时候你需要从头重建文件系统，可以运行 make clean 这会强制 make 重新构建 fs.img。

关注要点

磁盘上 inode 的格式由 struct dinode 中 fs.h定义。你需要特别关注 NDIRECT, NINDIRECT, MAXFILE，以及 addrs[] 的元素 struct dinode请参阅 xv6 教材中的图 8.3，该图展示了标准 xv6 inode 的结构示意图。

`fs.c` 中的代码负责在磁盘上查找文件的数据，位于 bmap() 中 fs.c。请仔细阅读并确保你理解它的功能。 bmap() 在读取和写入文件时都会被调用。写入时， bmap() 根据需要分配新块以存储文件内容，并在需要时分配一个间接块以存储块地址。

bmap() 处理两种块编号。其中 bn 参数是一个"逻辑块号"——即文件内的块号，相对于文件起始位置。其中的块号在 ip->addrs[]，以及传递给 bread()，是磁盘块编号。你可以查看 bmap() 作为将文件逻辑块号映射到磁盘块号的工具。

你的任务

修改 bmap() 使其在直接块和一级间接块的基础上，实现一个二级间接块。为了给新的二级间接块腾出空间，你需要将直接块的数量从 12 个减少到 11 个；不允许修改磁盘上 inode 的大小。 ip->addrs[] 的前 11 个元素应为直接块；第 12 个应为一级间接块（与当前相同）；第 13 个应为你新增的二级间接块。当 bigfile 写入 65803 个块，且 usertests 成功运行时，本练习即告完成： 
$ bigfile
..................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................
wrote 65803 blocks
done; ok
$ usertests
...
ALL TESTS PASSED
$

bigfile 运行至少需要一分半钟。

Hints:

  • 请确保你理解 bmap()。画出 ip->addrs[]、间接块、二级间接块及其所指向的一级间接块，以及数据块之间关系的示意图。请确保你理解为什么添加一个二级间接块会使文件最大大小增加 256*256 个块（实际上是 -1，因为你需要将直接块数量减少一个）。
  • 思考如何使用逻辑块号对二级间接块及其所指向的间接块进行索引。
  • 如果你修改了 NDIRECT，你可能需要更改 addrs[] 中 struct inode 中 file.h。确保 struct inode 和 struct dinode 在其 addrs[] 数组中具有相同数量的元素。
  • 如果你修改了 NDIRECT，确保创建一个新的 fs.img，因为 mkfs 使用 NDIRECT 来构建文件系统。
  • 如果你的文件系统进入异常状态（例如由于崩溃），请删除 fs.img （在 Unix 下执行此操作，而非在 xv6 中）。 make 将为你构建一个新的干净的文件系统镜像。
  • 不要忘记 brelse() 你分配的每个块 bread().
  • 你应该仅在需要时分配间接块和双重间接块，与原始实现一样 bmap().
  • 请确保 itrunc 释放文件的所有块，包括双重间接块。

符号链接

在本练习中，你将为 xv6 添加符号链接支持。符号链接（或软链接）通过路径名引用被链接的文件；当符号链接被打开时，内核会沿着该链接找到所指向的文件。符号链接与硬链接类似，但硬链接只能指向同一磁盘上的文件，而符号链接可以跨磁盘设备。尽管 xv6 不支持多设备，实现这一系统调用是理解路径名查找机制的良好练习。

你的任务

你将实现 symlink(char *target, char *path) 系统调用，该调用在 path 处创建一个新的符号链接，指向 target 所指定的文件。更多信息请参阅 man 手册中的 symlink 条目。如需测试，请将 symlinktest 添加到 Makefile 并运行。当测试产生如下输出时（包括 usertests 通过），说明你的解答已完成。 

$ symlinktest
Start: test symlinks
test symlinks: ok
Start: test concurrent symlinks
test concurrent symlinks: ok
$ usertests
...
ALL TESTS PASSED
$

Hints:

  • 首先，为 symlink 创建一个新的系统调用编号，在 user/usys.pl 和 user/user.h 中添加相应条目，并在 kernel/sysfile.c 中实现一个空的 sys_symlink。
  • 在 kernel/stat.h 中添加一种新的文件类型（T_SYMLINK）以表示符号链接。
  • 在 kernel/fcntl.h 中添加一个新标志，(O_NOFOLLOW），可与 open 系统调用。请注意，传递给 open 使用按位或运算符组合这些标志，因此你的新标志不应与任何现有标志重叠。这样，一旦你将 user/symlinktest.c 添加到 Makefile 中，就可以编译它了。
  • 实现 symlink(target, path) 系统调用，在 path 处创建一个指向 target 的新符号链接。注意，target 不需要存在，系统调用即可成功。你需要选择某个位置来存储符号链接的目标路径，例如，存储在 inode 的数据块中。 symlink 应返回一个整数，表示成功（0）或失败（-1），类似于 link 和 unlink.
  • 修改 open 系统调用以处理路径指向符号链接的情况。如果文件不存在， open 当进程指定 O_NOFOLLOW 在标志位中传入 open, open 应打开符号链接文件本身（而不是跟随符号链接）。
  • 如果被链接的文件本身也是符号链接，则必须递归地跟随链接，直到到达一个非链接文件为止。如果链接构成环路，则必须返回错误码。你可以通过在链接深度达到某一阈值（例如 10）时返回错误码来近似处理这种情况。
  • 其他系统调用（例如 link 和 unlink）不得跟随符号链接；这些系统调用直接作用于符号链接本身。
  • 本实验无需处理指向目录的符号链接。
