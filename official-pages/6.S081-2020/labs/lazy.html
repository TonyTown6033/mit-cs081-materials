实验：xv6 惰性页面分配

操作系统可以利用页表硬件实现许多巧妙的技巧，其中之一便是对用户态堆内存进行惰性分配。xv6 应用程序通过 sbrk() 系统调用向内核申请堆内存。在我们提供的内核实现中，sbrk() 会分配物理内存并将其映射到进程的虚拟地址空间。对于较大的内存申请，内核分配并映射内存可能耗费大量时间。举例来说，1 GB 内存由 262,144 个 4096 字节的页面组成——即便每次分配的开销很小，总量仍然巨大。此外，某些程序申请的内存远多于实际使用量（例如用于实现稀疏数组），或在实际使用前很久就提前申请内存。为了让 sbrk() 在这些情况下能更快返回，成熟的内核会采用惰性方式分配用户内存。具体而言，sbrk() 并不立即分配物理内存，而只是记录哪些用户地址已被分配，并在用户页表中将这些地址标记为无效。当进程首次尝试访问某个惰性分配的页面时，CPU 会触发缺页错误，内核随即响应，分配物理内存、将其清零并完成映射。本实验中，你将为 xv6 添加这一惰性分配功能。

去除 sbrk() 中的内存分配

你的第一个任务是删除 sbrk(n) 系统调用实现中的页面分配逻辑，该实现位于 sysproc.c 中的 sys_sbrk() 函数。sbrk(n) 系统调用将进程的内存大小增加 n 字节，并返回新分配区域的起始地址（即原来的大小）。修改后的 sbrk(n) 只需将进程的大小（myproc()->sz）增加 n 并返回旧的大小，而不实际分配内存——因此你需要删除对 growproc() 的调用（但仍然需要更新进程的大小！）。

试着预测一下这个修改会带来什么结果：哪些地方会出错？

进行此修改，启动 xv6，然后输入 echo hi 到 shell。你应该会看到类似如下的输出： 

init: starting sh
$ echo hi
usertrap(): unexpected scause 0x000000000000000f pid=3
            sepc=0x0000000000001258 stval=0x0000000000004008
va=0x0000000000004000 pte=0x0000000000000000
panic: uvmunmap: not mapped
"usertrap(): ..." 消息来自 trap.c 中的用户态陷阱处理程序；它捕获到了一个不知道如何处理的异常。请确保你理解此页错误发生的原因。"stval=0x0..04008" 表示导致页错误的虚拟地址为 0x4008。

惰性分配

修改 `trap.c` 中的代码，通过在发生错误的地址处映射一个新分配的物理内存页来响应来自用户态的页错误，然后返回用户态让进程继续执行。你应该将代码添加在 printf 产生"usertrap(): ..."消息的调用。修改 xv6 内核中其他任何必要的代码，以使 echo hi 使其正常工作。
以下是一些提示：
  • 你可以在 `usertrap()` 中通过检查 `r_scause()` 是否为 13 或 15 来判断某个故障是否为缺页故障。
  • r_stval() 返回 RISC-V stval 寄存器，其中包含导致缺页故障的虚拟地址。
  • 从 vm.c 中的 uvmalloc() 借鉴代码，这是 sbrk()（通过 growproc()）所调用的函数。你需要调用 kalloc() 和 mappages()。
  • 使用 PGROUNDDOWN(va) 将发生错误的虚拟地址向下对齐到页面边界。
  • uvmunmap() 会触发 panic；请修改它，使其在某些页面未映射时不触发 panic。
  • 如果内核崩溃，请在 kernel/kernel.asm 中查找 sepc 的值。
  • 使用你的 vmprint （来自 pgtbl 实验的函数）打印页表的内容。
  • 如果出现错误 "incomplete type proc"，请先包含 "spinlock.h"，再包含 "proc.h"。

如果一切顺利，你的惰性分配代码应能使 echo hi 正常运行。你应该会看到至少一次缺页错误（从而触发惰性分配），也可能出现两次。

Lazytests 与 Usertests

我们为你提供了 lazytests，这是一个 xv6 用户程序，用于测试一些可能对你的惰性内存分配器造成压力的特定场景。请修改你的内核代码，使以下两者全部 lazytests 和 usertests 通过。

  • 处理 sbrk() 的负数参数。
  • 若进程在高于任何 sbrk() 已分配范围的虚拟内存地址上发生缺页错误，则终止该进程。
  • 正确处理 fork() 中从父进程到子进程的内存复制。
  • 处理以下情况：进程将一个通过 sbrk() 获得的有效地址传递给 read 或 write 等系统调用，但该地址对应的内存尚未分配。
  • 正确处理内存不足的情况：若缺页错误处理程序中 kalloc() 失败，则终止当前进程。
  • 处理用户栈下方无效页面上发生的缺页错误。
