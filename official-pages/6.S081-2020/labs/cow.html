实验：xv6 的写时复制 fork

虚拟内存提供了一层间接性：内核可以通过将 PTE 标记为无效或只读来拦截内存引用，从而触发页面错误，并可以通过修改 PTE 来改变地址的含义。计算机系统领域有一句名言：任何系统问题都可以通过增加一层间接性来解决。惰性分配实验提供了一个例子，本实验则探讨另一个例子：写时复制 fork。

要开始本实验，请切换到 cow 分支： 

$ git fetch
$ git checkout cow
$ make clean

问题描述

xv6 中的 fork() 系统调用会将父进程的所有用户态内存复制到子进程中。如果父进程占用内存较大，复制过程可能耗费大量时间。更糟糕的是，这些工作往往大部分都是徒劳的；例如，子进程在 fork() 之后紧接着调用 exec()，将导致子进程丢弃已复制的内存，而其中大部分可能根本未被使用过。另一方面，如果父子进程都需要使用某个页面，且其中一方或双方对其进行了写操作，则确实需要进行复制。

解决方案

写时复制（COW）fork() 的目标是推迟为子进程分配和复制物理内存页的时机，直到真正需要时才进行复制（如果需要的话）。

COW fork() 仅为子进程创建一个页表，其中用户内存的 PTE 指向父进程的物理页。COW fork() 将父子进程中所有用户态 PTE 均标记为不可写。当任意一个进程尝试写入这些 COW 页时，CPU 将触发页面错误。内核的页面错误处理程序检测到这种情况后，会为发生错误的进程分配一个物理内存页，将原始页内容复制到新页中，并修改该进程中对应的 PTE 以指向新页，同时将该 PTE 标记为可写。页面错误处理程序返回后，用户进程便可以对其私有的页面副本进行写操作。

COW fork() 使得释放实现用户内存的物理页变得稍加复杂。某个物理页可能同时被多个进程的页表所引用，只有当最后一个引用消失时，该物理页才应被释放。

实现写时复制

您的任务是在 xv6 内核中实现写时复制 fork。如果您修改后的内核能够成功执行 cowtest 和 usertests 程序，则表示任务完成。

为了帮助你测试你的实现，我们提供了一个名为 cowtest 的 xv6 程序（源代码位于 user/cowtest.c）。cowtest 运行各种测试，但即使是第一个测试也会在未修改的 xv6 上失败。因此，最初你会看到： 

$ cowtest
simple: fork() failed
$
"simple"测试分配了超过一半的可用物理内存，然后调用 fork()。由于没有足够的空闲物理内存为子进程提供父进程内存的完整副本，fork 失败。

完成后，您的内核应通过 cowtest 和 usertests 中的所有测试。即： 

$ cowtest
simple: ok
simple: ok
three: zombie!
ok
three: zombie!
ok
three: zombie!
ok
file: ok
ALL COW TESTS PASSED
$ usertests
...
ALL TESTS PASSED
$

以下是一个合理的攻略方案。

  1. 修改 `uvmcopy()`，将父进程的物理页映射到子进程，而不是分配新页。清除 PTE_W 在子进程和父进程的 PTE 中。
  2. 修改 `usertrap()`，使其能够识别缺页错误。当 COW 页面发生缺页错误时，使用 `kalloc()` 分配一个新页面，将旧页面的内容复制到新页面，并将新页面通过以下方式安装到 PTE 中： PTE_W 集合。
  3. 确保每个物理页面在最后一个引用它的 PTE 消失时才被释放——而不是更早。一个好的方法是，为每个物理页面维护一个"引用计数"，记录有多少用户页表引用了该页面。当 kalloc() 在 fork 导致子进程共享该页面时增加页面的引用计数，并在任何进程将该页面从其页表中移除时减少页面的计数。 kfree() 只有当页面的引用计数为零时，才应将其放回空闲列表。可以将这些计数保存在一个固定大小的整数数组中。你需要设计一种方案来确定数组的索引方式以及如何选择其大小。例如，可以用页面的物理地址除以 4096 作为数组索引，并将数组元素个数设置为等于由 kinit() 在 kalloc.c 中。
  4. 修改 copyout()，使其在遇到 COW 页面时采用与处理缺页故障相同的方案。

一些提示：

  • 惰性分配实验很可能已经让你熟悉了与写时复制相关的大部分 xv6 内核代码。但是，请不要在你的惰性分配解答的基础上完成本实验；请按照上述要求，从一份全新的 xv6 代码开始。
  • 为每个 PTE 记录其是否为 COW 映射可能会有所帮助。你可以使用 RISC-V PTE 中的 RSW（软件保留）位来实现这一点。
  • usertests 探测了一些 cowtest 未测试的场景，因此不要忘记检查两者的所有测试均能通过。
  • 一些关于页表标志位的有用宏和定义位于 kernel/riscv.h.
  • 如果发生 COW 缺页故障且没有可用内存，则应终止该进程。
