实验指南

作业难度

每项作业均标注了其难度等级：

  • 简单：不到一小时。这些练习通常是后续练习的热身。

  • 中等：1–2 小时。

  • 困难：超过 2 小时。这类练习通常不需要太多代码，但要写对却颇具技巧性。

以上时间仅为我们的粗略预估。部分选做作业我们没有参考答案，难度评级也只是大致猜测。如果你发现自己在某项作业上花费的时间超出预期，请在 Piazza 上留言或前来参加答疑课时。

这些练习通常不需要太多代码（从几十行到几百行不等），但代码在概念上较为复杂，细节往往至关重要。因此，请务必完成实验的指定阅读材料，通读相关文件，并查阅相关文档（RISC-V 手册等可在 参考资料页面）之前，请先阅读并理解相关的 xv6 章节内容。只有当你对作业要求和解题思路有了充分把握之后，再开始编写代码。开始编码时，请将解决方案分小步骤实现（作业通常会提示如何将问题拆分为更小的步骤），并在继续下一步之前验证每个步骤是否正确。

警告：不要在实验截止日期的前一晚才开始做实验；将实验分散到多天、分多次完成会大大提高效率。操作系统内核中的错误表现往往令人困惑，可能需要大量思考和仔细调试才能理解并修复。

调试技巧

以下是一些调试解答的技巧：

  • 确保你理解 C 语言和指针。Kernighan 与 Ritchie 所著的《The C programming language (second edition)》是对 C 语言的简明描述。以下是一些有用的指针练习： 这里除非你已经对 C 语言了如指掌，否则不要跳过或略读上面的指针练习。如果你没有真正理解 C 语言中的指针，你将在实验中遭受无尽的痛苦与折磨，最终只能以惨痛的方式弄懂它们。相信我们——你不会想知道"惨痛的方式"究竟意味着什么。

    以下几种常见的指针惯用法尤其值得牢记：

    • 如果 int *p = (int*)100，然后 (int)p + 1 和 (int)(p + 1) 是不同的数字：第一个是 101 但第二个是 104。当将整数与指针相加时（如第二种情况），该整数会隐式地乘以指针所指向对象的大小。
    • p[i] 其定义与以下表达式相同 *(p+i)，指向 p 所指内存中第 i 个对象。当对象大小超过一个字节时，上述加法规则使该定义仍然成立。
    • &p[i] 与以下表达式等价 (p+i)，得到 p 所指内存中第 i 个对象的地址。

    尽管大多数 C 程序无需在指针与整数之间进行强制类型转换，但操作系统却经常需要这样做。每当看到涉及内存地址的加法运算时，请思考这是整数加法还是指针加法，并确认被加的值是否已经过适当的乘法处理。

  • 如果某道练习已部分完成，请通过提交代码来保存进度。若后续出现问题，可以回滚到该检查点并以更小的步骤继续推进。如需深入了解 Git，请参阅 Git 用户手册，或者，您也可以参考这份 面向计算机科学的 Git 概览 ，可能会对您有所帮助。

  • 如果某项测试未通过，请务必弄清楚代码失败的原因。插入打印语句，直到明确问题所在。

  • 您可能会发现打印语句产生了大量输出需要检索；一种方法是运行 make qemu 内部 script （运行 man script 在你的机器上），它会将所有控制台输出记录到一个文件中，你随后可以对其进行搜索。不要忘记退出 script.

  • 在许多情况下，打印语句已经足够，但有时能够逐步执行某些汇编代码或检查栈上的变量会很有帮助。要在 xv6 中使用 gdb，请在一个窗口中运行 make make qemu-gdb 在另一个窗口中运行 gdb （或 riscv64-linux-gnu-gdb），设置断点，然后输入 'c'（continue，继续），xv6 将运行直到命中断点。（参见 GNU 调试器使用指南 以获取有用的 GDB 技巧。）

  • 如果你想查看编译器为内核生成的汇编代码，或者想找出某个特定内核地址处的指令，请参见文件 kernel.asm，该文件由 Makefile 在编译内核时生成。（Makefile 还会为所有用户程序生成 .asm 。）

  • 如果内核发生崩溃（panic），它将打印一条错误信息，列出崩溃时程序计数器的值；你可以搜索 kernel.asm 要找出程序崩溃时程序计数器所在的函数，或者你可以运行 addr2line -e kernel/kernel pc值 （运行 man addr2line 详情请参阅相关说明）。如果你想获取回溯信息，请使用 gdb 重新启动：在一个窗口中运行 'make qemu-gdb'，在另一个窗口中运行 gdb（或 riscv64-linux-gnu-gdb），在 panic 处设置断点（'b panic'），然后输入 'c'（continue）继续执行。当内核触发断点时，输入 'bt' 以获取回溯信息。

  • 如果你的内核挂起（例如，由于死锁）或无法继续执行（例如，由于执行内核指令时发生页错误），你可以使用 gdb 找出其挂起位置。在一个窗口中运行 `make qemu-gdb`，在另一个窗口中运行 gdb（`riscv64-linux-gnu-gdb`），然后输入 `c`（continue）继续执行。当内核出现挂起时，在 qemu-gdb 窗口中按 Ctrl-C，然后输入 `bt` 获取回溯信息。

  • qemu 有一个"监视器"，让你可以查询模拟机器的状态。你可以通过输入 control-a c 来进入它（"c"代表控制台）。一个特别有用的监视器命令是 info mem 打印页表。你可能需要使用 cpu 命令来选择核心 info mem 查看，或者你可以通过以下命令启动 qemu： make CPUS=1 qemu 使其只使用单个核心。
花时间学习上述工具是非常值得的。
