sleep

为 xv6 实现 UNIX 程序 sleep ；你的 sleep 应根据用户指定的 tick 数暂停执行。tick 是 xv6 内核定义的时间单位，即定时器芯片两次中断之间的时间间隔。你的解答应写在文件 user/sleep.c.

一些提示：

  • 开始编写代码之前，请阅读 xv6 书.
  • 的第 1 章。参考 user/ 中的一些其他程序（例如， user/echo.c, user/grep.c，以及 user/rm.c）以了解如何获取传递给程序的命令行参数。
  • 如果用户忘记传递参数，sleep 应打印一条错误信息。
  • 命令行参数以字符串形式传递；你可以使用 atoi （参见 user/ulib.c）将其转换为整数。
  • 使用系统调用 sleep.
  • 参见 kernel/sysproc.c 以了解实现该 sleep 系统调用的 xv6 内核代码（查找 sys_sleep), user/user.h 以获取 sleep 的 C 定义，该定义可从用户程序中调用，以及 user/usys.S 以了解从用户代码跳转到内核以执行 sleep.
  • 请确保 main 调用 exit() 的汇编代码，以便退出你的程序。
  • 将你的 sleep 程序添加到 UPROGS 的 Makefile 中；完成后， make qemu 将编译你的程序，你就可以在 xv6 shell 中运行它了。
  • 参阅 Kernighan 和 Ritchie 的书 C程序设计语言（第二版） （K&R）以学习 C 语言。

在 xv6 shell 中运行该程序： 

      $ make qemu
      ...
      init: starting sh
      $ sleep 10
      (nothing happens for a little while)
      $

如果你的程序在如上所示运行时暂停，则说明你的解答正确。运行 make grade 以确认你是否通过了 sleep 测试。

注意， make grade 会运行所有测试，包括下面各实验的测试。如果你只想运行某个实验的评分测试，请输入： 

     $ ./grade-lab-util sleep
这将运行与 "sleep" 匹配的评分测试。或者，你也可以输入： 
     $ make GRADEFLAGS=sleep grade
效果相同。

pingpong

编写一个程序，使用 UNIX 系统调用在两个进程之间通过一对管道（每个方向一个）来"乒乓"传递一个字节。父进程应向子进程发送一个字节；子进程应打印 "<pid>: received ping"（其中 <pid> 为其进程 ID），将该字节写入管道发回给父进程，然后退出；父进程应从子进程读取该字节，打印 "<pid>: received pong"，然后退出。你的解答应写在以下文件中： user/pingpong.c.

一些提示：

  • 使用 pipe 以创建管道。
  • 使用 fork 以创建子进程。
  • 使用 read 从管道读取数据，以及 write 向管道写入数据。
  • 使用 getpid 以找到调用进程的进程 ID。
  • 将该程序添加到 UPROGS 在 Makefile 中。
  • 用户程序在 xv6 上可使用的库函数集合十分有限。你可以在 user/user.h；源代码（系统调用除外）位于 user/ulib.c, user/printf.c，以及 user/umalloc.c.

在 xv6 shell 中运行该程序，应产生如下输出： 

    $ make qemu
    ...
    init: starting sh
    $ pingpong
    4: received ping
    3: received pong
    $

如果你的程序在两个进程之间交换了一个字节并产生如上所示的输出，则你的解答是正确的。

primes /

使用管道编写一个并发版本的素数筛。该思路源自 Unix 管道的发明者 Doug McIlroy。页面中部的图示 此页面 及其周围的文字说明了具体实现方法。你的解答应放在文件 user/primes.c.

你的目标是使用 pipe 和 fork 来构建流水线。第一个进程将数字 2 到 35 送入流水线。对于每个素数，你需要安排创建一个进程，该进程通过一个管道从其左邻进程读取数据，并通过另一个管道向其右邻进程写入数据。由于 xv6 的文件描述符和进程数量有限，第一个进程可以在 35 处停止。

一些提示：

  • 注意关闭进程不再需要的文件描述符，否则在第一个进程到达 35 之前，你的程序就会耗尽 xv6 的资源。
  • 一旦第一个进程到达 35，它应等待整个流水线终止，包括所有子进程、孙进程等。因此，主 primes 进程应在所有输出打印完毕、所有其他 primes 进程退出后才退出。
  • Hint: read 当管道的写端关闭时，返回零。
  • 最简单的方式是直接写入 32 位（4 字节） int写入管道，而不是使用格式化的 ASCII I/O。
  • 你应该仅在需要时才创建管道中的进程。
  • 将该程序添加到 UPROGS 在 Makefile 中。

如果你的解决方案实现了基于管道的筛法并产生以下输出，则视为正确： 

    $ make qemu
    ...
    init: starting sh
    $ primes
    prime 2
    prime 3
    prime 5
    prime 7
    prime 11
    prime 13
    prime 17
    prime 19
    prime 23

    $

find

编写一个简单版本的 UNIX find 程序：在目录树中查找所有具有特定名称的文件。你的解决方案应写在文件 user/find.c.

一些提示：

  • 参阅 user/ls.c，了解如何读取目录。
  • 使用递归以允许 find 进入子目录。
  • 不要递归进入 "." 和 ".."。
  • 对文件系统的更改在 qemu 的多次运行之间会持久保存；如需获得干净的文件系统，请运行 make clean 然后 make qemu.
  • 你需要使用 C 字符串。可参阅 K&R（C 语言教材），例如第 5.5 节。
  • 注意，== 不像在 Python 中那样比较字符串，请改用 strcmp()。
  • 将该程序添加到 UPROGS 在 Makefile 中。

如果文件系统包含相应文件，您的解决方案能产生以下输出，则视为正确： b 和 a/b): 

    $ make qemu
    ...
    init: starting sh
    $ echo > b
    $ mkdir a
    $ echo > a/b
    $ find . b
    ./b
    ./a/b
    $

xargs

编写一个简单版本的 UNIX `xargs` 程序：从标准输入读取每一行，并为每一行运行一个命令，将该行内容作为参数传递给该命令。你的解决方案应写在文件 user/xargs.c.

以下示例说明了 xargs 的行为： 
    $ echo hello too | xargs echo bye
    bye hello too
    $
注意，这里的命令是 "echo bye"，附加参数是 "hello too"，因此完整命令为 "echo bye hello too"，其输出为 "bye hello too"。

请注意，UNIX 上的 xargs 会进行一项优化，即每次向命令传入多个参数。我们不要求你实现这项优化。为了让 UNIX 上的 xargs 按照本实验所期望的方式运行，请使用 `-n` 选项并将其设置为 1。例如

    $ echo "1\n2" | xargs -n 1 echo line
    line 1
    line 2
    $

一些提示：

  • 使用 fork 和 exec 对输入的每一行调用该命令。使用 wait 在父进程中等待子进程完成命令。
  • 要逐行读取输入，请每次读取一个字符，直到出现换行符（`'\n'`）为止。
  • kernel/param.h 声明了 MAXARG，如果你需要声明一个 argv 数组，这可能会很有用。
  • 将该程序添加到 UPROGS 在 Makefile 中。
  • 对文件系统的更改在 qemu 的多次运行之间会持久保存；如需获得干净的文件系统，请运行 make clean 然后 make qemu.

xargs、find 和 grep 可以很好地组合使用： 

  $ find . b | xargs grep hello
将对 "." 以下各目录中每个名为 b 的文件运行 "grep hello"。

要测试你的 xargs 解决方案，请运行 shell 脚本 xargstest.sh。如果输出如下内容，则说明你的解决方案正确： 

  $ make qemu
  ...
  init: starting sh
  $ sh < xargstest.sh
  $ $ $ $ $ $ hello
  hello
  hello
  $ $
你可能需要回头修复 find 程序中的 bug。输出中有很多 $ 因为 xv6 shell 没有意识到它正在处理来自文件而非控制台的命令，并会为文件中的每条命令打印一个 $ 。

  • 编写一个 uptime 程序，使用 uptime 系统调用以 tick 为单位打印系统运行时间。
