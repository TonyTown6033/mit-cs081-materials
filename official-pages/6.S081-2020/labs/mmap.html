实验：mmap

的 mmap 和 munmap 系统调用允许 UNIX 程序对其地址空间进行详细的控制。它们可用于在进程之间共享内存，将文件映射到进程地址空间，并作为用户级页面错误方案的一部分，例如讲座中讨论的垃圾收集算法。在本实验中，您将添加 mmap 和 munmap 到 xv6，重点关注内存映射文件。

获取实验室的 xv6 源代码并查看 mmap branch: 

  $ git fetch
  $ git checkout mmap
  $ make clean

手册页（运行 man 2 mmap) 显示此声明 mmap: 

void *mmap(void *addr, size_t length, int prot, int flags,
           int fd, off_t offset);

mmap 可以通过多种方式调用，但本实验仅需要其与内存映射文件相关的功能的子集。你可以假设 addr 始终为零，这意味着内核应该决定映射文件的虚拟地址。 mmap 返回该地址，如果失败则返回 0xffffffffffffffff。 length 是要映射的字节数；它可能与文件的长度不同。 prot 指示内存是否应映射为可读、可写和/或可执行；你可以假设 prot 是 PROT_READ 或 PROT_WRITE 或两者兼而有之。 flags 将是 MAP_SHARED，这意味着对映射内存的修改应该写回文件，或者 MAP_PRIVATE，这意味着他们不应该。您不必在中实现任何其他位 flags. fd 是要映射的文件的打开文件描述符。你可以假设 offset 为零（它是文件中要映射的起点）。

如果映射的进程相同就可以了 MAP_SHARED 文件做 不 共享物理页面。

munmap(addr, length) 应删除指定地址范围内的 mmap 映射。如果进程修改了内存并已映射 MAP_SHARED，修改应首先写入文件。安 munmap 调用可能只覆盖 mmap 区域的一部分，但您可以假设它将在开始、结束或整个区域取消映射（但不会在区域中间打孔）。

你应该实施足够的 mmap 和 munmap 功能使 mmaptest 测试程序工作。如果 mmaptest 不使用 mmap 功能，您不需要实现该功能。

以下是一些提示：

  • 首先添加 _mmaptest 到 UPROGS, 和 mmap 和 munmap 系统调用，以获得 user/mmaptest.c 来编译。现在，只需从以下位置返回错误 mmap 和 munmap。我们定义 PROT_READ 等为你 kernel/fcntl.h。运行 mmaptest，这将在第一次 mmap 调用时失败。
  • 延迟填充页表，以响应页错误。也就是说， mmap 不应分配物理内存或读取文件。相反，请在页面错误处理代码中执行此操作（或由其调用） usertrap，如惰性页面分配实验室中所示。偷懒的原因是为了确保 mmap 大文件的速度很快，而且 mmap 大于物理内存的文件是可能的。
  • 跟踪什么 mmap 已映射每个进程。定义一个对应第15讲中介绍的VMA（虚拟内存区域）的结构体，记录了创建的虚拟内存范围的地址、长度、权限、文件等 mmap。由于 xv6 内核在内核中没有内存分配器，因此可以声明固定大小的 VMA 数组并根据需要从该数组进行分配。 16 的大小应该足够了。
  • 实施 mmap：在进程的地址空间中找到一个未使用的区域来映射文件，并将VMA添加到进程的映射区域表中。 VMA 应该包含一个指向 struct file 对于被映射的文件； mmap 应该增加文件的引用计数，以便在文件关闭时该结构不会消失（提示：请参阅 filedup）。运行 mmaptest：第一个 mmap 应该会成功，但是第一次访问 mmap 内存会导致页面错误并终止 mmaptest.
  • 添加代码以导致 mmap 区域中的页错误分配物理内存页，将相关文件的 4096 字节读入该页，并将其映射到用户地址空间。读取文件 readi，它采用一个偏移量参数来读取文件（但是您必须锁定/解锁传递给的 inode readi）。不要忘记在页面上正确设置权限。运行 mmaptest;它应该到达第一个 munmap.
  • 实施 munmap：找到地址范围的VMA并取消映射指定的页面（提示：使用 uvmunmap）。如果 munmap 删除以前的所有页面 mmap，它应该减少相应的引用计数 struct file。如果未映射的页面已被修改并且文件已映射 MAP_SHARED，将页面写回文件。看看 filewrite 寻求灵感。
  • 理想情况下，您的实现只会写回 MAP_SHARED 程序实际修改的页面。脏点（D) 在 RISC-V PTE 中表示页面是否已被写入。然而， mmaptest 不检查非脏页是否未被写回；因此你可以不用看就可以写回页面 D bits.
  • 修改 exit 取消映射进程的映射区域，就像 munmap 被召唤了。运行 mmaptest; mmap_test 应该通过，但可能不会 fork_test.
  • 修改 fork 确保子级具有与父级相同的映射区域。不要忘记增加 VMA 的引用计数 struct file。在子进程的页面错误处理程序中，可以分配一个新的物理页面，而不是与父进程共享页面。后者会更酷，但需要更多的实施工作。运行 mmaptest;它应该通过两个 mmap_test 和 fork_test.

可选挑战

  • 如果两个进程具有相同的文件 mmap-ed（如 fork_test），分享他们的物理页面。您将需要物理页上的引用计数。
  • 您的解决方案可能会为从 mmap 文件读取的每个页面分配一个新的物理页面，即使数据也在缓冲区高速缓存的内核内存中。修改您的实现以使用该物理内存，而不是分配新页面。这要求文件块的大小与页面相同（设置 BSIZE 至 4096）。您需要将 mmap 块固定到缓冲区高速缓存中。您需要担心引用计数。
  • 消除延迟分配的实现和 mmap 文件的实现之间的冗余。 （提示：为惰性分配区域创建一个 VMA。）
  • 修改 exec 对二进制文件的不同部分使用 VMA，以便获得按需分页的可执行文件。这将使启动程序更快，因为 exec 不必从文件系统读取任何数据。
  • 实现页出和页入：当物理内存不足时，让内核将进程的某些部分移至磁盘。然后，当进程引用调出的内存时，对其进行分页。
