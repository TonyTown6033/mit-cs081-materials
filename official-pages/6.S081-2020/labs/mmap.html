实验：mmap

该 mmap 和 munmap 系统调用允许 UNIX 程序对其地址空间进行精细控制。它们可用于在进程间共享内存、将文件映射到进程地址空间，以及作为用户级页面错误方案的一部分（例如课堂上讨论的垃圾回收算法）。在本实验中，你将添加 mmap 和 munmap 到 xv6，重点关注内存映射文件。

获取本实验的 xv6 源代码并切换到 mmap branch: 

  $ git fetch
  $ git checkout mmap
  $ make clean

`man 2 mmap`) describes the `mmap` system call. The purpose of this lab is to implement the `mmap` and `munmap` system calls to add them to xv6. --- 手册页（运行 `man 2 mmap`）描述了 `mmap` 系统调用。本实验的目的是实现 `mmap` 和 `munmap` 系统调用，并将它们添加到 xv6 中。 man 2 mmap）展示了 mmap: 

void *mmap(void *addr, size_t length, int prot, int flags,
           int fd, off_t offset);

mmap 可以通过多种方式调用，但本实验仅要求实现与文件内存映射相关的部分功能。你可以假设 addr 将始终为零，这意味着内核应自行决定将文件映射到哪个虚拟地址。 mmap 返回该地址，若失败则返回 0xffffffffffffffff。 length 是要映射的字节数；它可能与文件的长度不同。 prot 指示内存是否应被映射为可读、可写和/或可执行；你可以假设 prot 是 PROT_READ 或 PROT_WRITE 或两者皆有。 flags 将为 MAP_SHARED，表示对映射内存的修改应写回文件，或者 MAP_PRIVATE，表示不应写回。你不必实现 flags. fd 是要映射文件的打开文件描述符。你可以假设 offset 为零（即文件中开始映射的起始位置）。

映射同一个 MAP_SHARED 文件的进程 不 共享物理页面，这是允许的。

munmap(addr, length) 应删除指定地址范围内的 mmap 映射。如果进程已修改该内存且以 MAP_SHARED方式映射，则应先将修改写入文件。一次 munmap 调用可能只覆盖 mmap 映射区域的一部分，但你可以假设它只会从起始处、末尾处解除映射，或解除整个区域的映射（而不会在区域中间打孔）。

你需要实现足够的 mmap 和 munmap 功能以使 mmaptest 测试程序正常运行。如果 mmaptest 未使用某个 mmap 特性，则无需实现该特性。

以下是一些提示：

  • 首先将 _mmaptest 添加到 UPROGS，以及 mmap 和 munmap 系统调用，以便使 user/mmaptest.c 能够编译。目前，只需让 mmap 和 munmap返回错误即可。我们已定义了 PROT_READ 等内容为您在 kernel/fcntl.h。运行 mmaptest，程序将在第一次 mmap 调用时失败。
  • 惰性填充页表，以响应缺页错误。也就是说， mmap 不应分配物理内存或读取文件。而应在缺页错误处理代码中（或由其调用的函数中）完成这些操作， usertrap，如惰性分配实验中那样。采用惰性方式的原因是确保 mmap 对大文件的操作速度很快，并且 mmap 对超出物理内存大小的文件的操作成为可能。
  • 跟踪每个进程中 mmap 所映射的内容。定义一个与第15讲中描述的 VMA（虚拟内存区域）对应的结构体，用于记录由 mmap创建的虚拟内存范围的地址、长度、权限、文件等信息。由于 xv6 内核中没有内核内存分配器，可以声明一个固定大小的 VMA 数组，并按需从中分配。大小为 16 应该足够。
  • 实现 mmap：在进程的地址空间中找到一个未使用的区域来映射文件，并在进程的已映射区域表中添加一个 VMA。该 VMA 应包含一个指向 struct file 用于被映射的文件； mmap 应增加文件的引用计数，以确保在文件关闭时该结构不会消失（提示：参见 filedup). 运行 mmaptest：第一个 mmap 应成功，但首次访问 mmap 映射的内存将导致缺页错误并终止 mmaptest.
  • 添加代码，使 mmap 映射区域中的缺页错误能够分配一页物理内存，将相关文件的 4096 字节读入该页，并将其映射到用户地址空间。使用 readi，该函数接受一个偏移量参数用于在文件中读取数据（但你需要对传入的 inode 进行加锁/解锁 readi。别忘了正确设置页面的权限。运行 mmaptest；它应该到达第一个 munmap.
  • 实现 munmap：找到该地址范围对应的 VMA，并取消映射指定页面（提示：使用 uvmunmap）。如果 munmap 移除先前的所有页面 mmap，它应该递减相应的引用计数 struct file。如果某个已取消映射的页面已被修改，且文件是以 MAP_SHARED方式映射的，则将该页面写回文件。参考 filewrite 以获取灵感。
  • 理想情况下，你的实现应只将程序实际修改过的页面写回。 MAP_SHARED RISC-V PTE 中的脏位（D）指示某页面是否已被写入。然而， mmaptest 不会检查未被修改的页面是否被写回；因此，你可以在不查看 D 位的情况下直接写回页面。
  • 修改 exit 以取消进程的映射区域，如同已调用 munmap 一样。运行 mmaptest; mmap_test 应该通过，但可能不会 fork_test.
  • 修改 fork 以确保子进程与父进程拥有相同的映射区域。不要忘记为 VMA 的引用计数加一 struct file。在子进程的缺页处理程序中，可以分配一个新的物理页，而不必与父进程共享页面。后者会更优雅，但需要更多的实现工作。运行 mmaptest；它应该同时通过 mmap_test 和 fork_test.

运行 usertests 以确保所有功能仍然正常工作。

可选挑战

  • 如果两个进程 mmap 了同一个文件（如 fork_test），则共享它们的物理页。你需要对物理页维护引用计数。
  • 你的实现可能会为从 mmap 文件中读取的每一页都分配一个新的物理页，即使这些数据已经以缓冲区缓存的形式存在于内核内存中。修改你的实现，直接使用该物理内存，而不是分配新页。这要求文件块与页的大小相同（将 BSIZE 设置为 4096）。你需要将 mmap 的文件块固定在缓冲区缓存中，并需要处理引用计数问题。
  • 消除惰性分配实现与 mmap 文件实现之间的冗余代码。（提示：为惰性分配区域创建一个 VMA。）
  • 修改 exec 为二进制文件的不同段使用 VMA，从而实现按需分页的可执行文件。这将加快程序启动速度，因为 exec 无需从文件系统读取任何数据。
  • 实现页面换出与换入：当物理内存不足时，内核将进程的部分内容移至磁盘；当进程访问已换出的内存时，再将其换入。
