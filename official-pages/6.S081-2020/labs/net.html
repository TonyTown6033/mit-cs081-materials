背景

在编写代码之前，您可能会发现阅读 xv6 书.

你将使用一个名为 E1000 的网络设备来处理网络通信。对于 xv6（以及你编写的驱动程序）而言，E1000 看起来就像一块连接到真实以太网局域网（LAN）的真实硬件。实际上，你的驱动程序所通信的 E1000 是由 qemu 提供的模拟设备，连接到一个同样由 qemu 模拟的局域网。在这个模拟局域网中，xv6（"客户机"）的 IP 地址为 10.0.2.15。Qemu 还会安排运行 qemu 的计算机以 IP 地址 10.0.2.2 出现在该局域网中。当 xv6 使用 E1000 向 10.0.2.2 发送数据包时，qemu 会将该数据包投递给你运行 qemu 的（真实）计算机（"宿主机"）上的相应应用程序。

您将使用 QEMU 的"用户态网络栈"。QEMU 的文档中有关于用户态栈的更多信息 这里。我们已更新 Makefile，以启用 QEMU 的用户态网络协议栈和 E1000 网卡。

`kernel/e1000.c` 包含 E1000 的初始化代码以及你需要填写的用于发送和接收数据包的空函数。`kernel/e1000_dev.h` 包含 E1000 寄存器和标志位的定义，这些内容在 [Intel E1000 软件开发者手册](https://pdos.csail.mit.edu/6.828/2020/readings/8254x_GBe_SDM.pdf) 中有所描述。`kernel/net.c` 和 `kernel/net.h` 包含一个简单的网络协议栈，用于实现 [IP](https://en.wikipedia.org/wiki/Internet_Protocol)、[UDP](https://en.wikipedia.org/wiki/User_Datagram_Protocol) 和 [ARP](https://en.wikipedia.org/wiki/Address_Resolution_Protocol) 协议。这些文件还包含用于保存数据包的灵活数据结构（即 `mbuf`），以及用于向网络协议栈发送和接收数据包的函数。`kernel/pci.c` 包含在 xv6 启动时在 [PCI](https://en.wikipedia.org/wiki/Conventional_PCI) 总线上搜索 E1000 网卡的代码。 kernel/e1000.c 包含 E1000 的初始化代码，以及用于发送和接收数据包的空函数，您需要填写这些函数。 kernel/e1000_dev.h 包含 E1000 定义的寄存器及标志位，这些内容在 Intel E1000 软件开发人员手册. kernel/net.c 和 kernel/net.h 包含一个简单的网络栈，实现了 IP, UDP，以及 ARP 协议。这些文件还包含用于保存数据包的灵活数据结构的代码，称为 mbuf。最后， kernel/pci.c 包含在 xv6 启动时在 PCI 总线上搜索 E1000 网卡的代码。

该 e1000_init() `kernel/net.c` e1000.c 将 E1000 配置为从 RAM 中读取待发送的数据包，并将接收到的数据包写入 RAM。这种技术称为 DMA（直接内存访问），指的是 E1000 硬件直接向 RAM 写入数据包或从 RAM 读取数据包。

因为数据包可能以突发形式到达，其速度可能快于驱动程序的处理速度， e1000_init() 为 E1000 提供多个缓冲区，E1000 可以将接收到的数据包写入其中。E1000 要求这些缓冲区由内存中的一个"描述符"数组来描述；每个描述符包含一个内存地址，E1000 可以将接收到的数据包写入该地址。 struct rx_desc 描述了描述符的格式。描述符数组称为接收环，或接收队列。它是一个循环环，即当网卡或驱动程序到达数组末尾时，会回绕到数组开头。 e1000_init() 分配 mbuf 供 E1000 通过 DMA 写入的数据包缓冲区，使用 mbufalloc()。此外还有一个发送环，驱动将希望 E1000 发送的数据包放入其中。 e1000_init() 将两个环配置为大小 RX_RING_SIZE 和 TX_RING_SIZE.

当网络协议栈在 net.c 需要发送数据包时，它会调用 e1000_transmit() 包含待发送数据包的 mbuf。你的发送代码必须将指向数据包数据的指针放入 TX（发送）环中的一个描述符中。 struct tx_desc `E1000_TXD_STAT_DD` 位在描述符中以表示此情况）。 E1000_TXD_STAT_DD 描述符中的相应位来表示这一点）。

当 E1000 从以太网接收到每个数据包时，它首先将数据包 DMA 到下一个 RX（接收）环描述符所指向的 mbuf 中，然后产生一个中断。您的 e1000_recv() 代码必须扫描 RX 环并将每个新数据包的 mbuf 传递给网络栈（在 net.c）通过调用 net_rx()。随后，您需要分配一个新的 mbuf 并将其放入描述符中，以便当 E1000 再次到达 RX 环中的该位置时，能找到一个新的缓冲区供其 DMA 写入新数据包。

除了读写内存中的描述符环，你的驱动还需要通过 E1000 的内存映射控制寄存器与 E1000 进行交互，以检测何时有接收到的数据包可用，并通知 E1000 驱动已将待发送的数据包填入了一些 TX 描述符。全局变量 regs 保存指向 E1000 第一个控制寄存器的指针；你的驱动程序可以通过索引来访问其他寄存器 regs 作为一个数组。你需要使用索引 E1000_RDT 和 E1000_TDT 尤其如此。

实验：网络 在本实验中，您将为网络接口卡（NIC）编写一个 xv6 设备驱动程序。 在开始编写代码之前，请阅读 [xv6 书籍的第 5 章](../../xv6/book-riscv-rev1.pdf)，以及以下相关文件： * `kernel/e1000.c`（含 E1000 初始化及完整发送/接收函数存根） * `kernel/e1000_dev.h`（E1000 硬件及其寄存器的宏定义，摘自英特尔 E1000 软件开发手册） * `kernel/net.c`（网络协议栈） * `kernel/net.h`（网络协议栈的宏定义与结构定义） 执行 `make grade` 以运行本实验的评测程序。 ## 背景 在提交本实验的 `net.c` 解决方案之前，您需要先完成实验 [lazy](lazy.html)（已将相应提交合并至主线）。 我们将使用一种名为 E1000 的网络设备来处理网络通信。在 xv6（以及您将编写的驱动程序）看来，E1000 就像是连接到真实以太网局域网（LAN）的真实硬件。实际上，您的驱动程序将与 QEMU 提供的 E1000 模拟设备进行交互，该模拟设备连接到的是同样由 QEMU 模拟的局域网。在这个模拟局域网中，xv6（"访客"）的 IP 地址为 `10.0.2.15`，主机的 IP 地址为 `10.0.2.2`。 我们将使用 QEMU 的用户模式网络栈，详情请参见 [QEMU 文档](https://www.qemu.org/docs/master/system/net.html)。QEMU 的文档还涵盖了用户模式栈的更多内容。 我们在 `Makefile` 中提供的 QEMU 命令行对用户模式网络栈进行如下配置：`-netdev user,id=net0,hostfwd=tcp::26099-:26099` 和 `-device e1000,netdev=net0,bus=pcie.0`，以便在 QEMU 中运行 xv6。 ### 获取数据包 E1000 使用直接内存访问（DMA）技术，直接在 RAM 中读写数据包，不涉及 CPU。驱动程序需要为 E1000 分配一块 RAM 缓冲区，并告知 E1000 该缓冲区的内存地址。E1000 硬件负责将到达的数据包写入 RAM，并从 RAM 中读取待发送的数据包。 E1000 通过一个由"描述符"组成的环形队列（称为接收环或接收队列）来管理接收到的数据包，每个描述符包含 RAM 中的一个地址，E1000 可在此地址写入接收到的数据包。`struct rx_desc` 用于描述描述符格式。该环形队列由 `RX_RING_SIZE` 个描述符组成。在 `e1000_init()` 中，已将各描述符指向的 `mbuf` 数据包缓冲区全部分配完毕。`struct tx_desc` 用于描述发送描述符的格式，以及描述符指向的 `mbuf`。 这两个环形队列的工作方式类似于一个环形缓冲区：驱动程序告知硬件下一个应处理的位置（即"尾指针"），硬件在此位置之前完成处理，并更新"头指针"以通知驱动程序进度。xv6 的 `e1000_init()` 函数使用 `E1000_RDT` 和 `E1000_TDT` 寄存器来配置接收环和发送环的尾指针。 当 E1000 接收到一个数据包时，它首先对数据包做 DMA 处理，使其进入下一个 RX（接收）环描述符所指向的 `mbuf`，然后触发一个中断。您的 `e1000_recv()` 代码必须扫描整个 RX 环，并通过调用 `net_rx()` 将每个新数据包的 `mbuf` 交付给网络协议栈（在 `net.c` 中）。随后，您需要分配一个新的 `mbuf`，并将其放入描述符中，以便 E1000 下次接收数据包时能够再次使用该内存位置。 当 E1000 硬件想要发送一个数据包时，它首先从下一个 TX（发送）描述符所指向的 `mbuf` 中读取数据包，然后完成 DMA 传输并触发中断。您的 `e1000_transmit()` 代码必须将待发送的 `mbuf` 放入 TX 环的某个描述符中。 在发送一个完整数据包时，E1000 会请求硬件执行 CRC 校验，并在网络上传输该数据包。 在接收侧，E1000 会等待一个数据包出现在以太网上，对其执行 CRC 校验，如果数据包有效，则通过 DMA 将其写入接收环描述符所指向的内存。 您需要使用 E1000 软件开发手册（SDM）作为参考。以下 PDF 文件涵盖了驱动程序的关键部分： - 第 2 章：了解设备概览 - 第 3 章：了解数据包接收流程 - 第 4 章：了解数据包传输流程 - 第 13 章：了解 E1000 使用的寄存器 - 第 14 章：了解 E1000 初始化流程 ## 您的工作 您的工作是在 `kernel/e1000.c` 中完成 `e1000_transmit()` 和 `e1000_recv()` 函数，使驱动程序能够收发数据包。当 `make grade` 显示您的解决方案通过了所有测试时，即表示大功告成。 在编写 `e1000_transmit()` 时，请注意以下几点： * 首先，通过读取 `E1000_TDT` 控制寄存器，向 E1000 询问其等待下一个数据包的 TX 描述符环索引。 * 随后，检查该环是否溢出。若 `E1000_TXD_STAT_DD` 未在 `E1000_TDT` 索引对应的描述符中置位，说明 E1000 尚未发完之前的传输，应返回错误。 * 否则，使用 `mbuf_free()` 释放该描述符最后传输的 `mbuf`（如有）。 * 随后，填充描述符。`m->head` 指向内存中数据包的内容，`m->len` 为数据包长度。设置必要的 cmd 标志位（参见 E1000 手册第 3.3 节），并将指向 `mbuf` 的指针存储起来，以备日后释放。 * 最后，通过将 `E1000_TDT` 对 `TX_RING_SIZE` 取模后加一来更新尾指针。 * 若 `e1000_transmit()` 成功将 `mbuf` 加入环，则返回 0；若环已满，应释放该 `mbuf` 并返回 -1。 在编写 `e1000_recv()` 时，请注意以下几点： * 首先，通过读取 `E1000_RDT` 控制寄存器并加一再对 `RX_RING_SIZE` 取模，向 E1000 询问下一个等待处理的数据包所在的环索引。 * 随后，通过检查描述符 `status` 部分的 `E1000_RXD_STAT_DD` 标志位，判断是否有新数据包可用。若无，则停止处理。 * 否则，将 `mbuf` 的 `m->len` 更新为描述符中记录的长度。使用 `net_rx()` 将 `mbuf` 交付给网络协议栈。 * 随后，使用 `mbufalloc()` 分配一个新的 `mbuf` 来替换刚刚交给网络协议栈的那个（注意初始化包头偏移量 `m->head = m->buf + MBUF_DEFAULT_HEAD_ROOM`）。将其数据指针存入描述符，并将描述符的状态位清零。 * 最后，将 `E1000_RDT` 寄存器更新为所处理的最后一个描述符的索引。 * `e1000_init()` 使用 `mbuf` 初始化 RX 环描述符，您可能希望了解其工作方式。 * 在某个时间点，到达的数据包总数将超过环的大小（16 个）；请确保您的代码能够正确处理这种情况。 您将需要锁来应对如下情形：xv6 可能从多个进程使用 E1000，或者在内核线程等待数据包到达时发生中断。 ## 提示

首先在以下位置添加打印语句 e1000_transmit() 和 e1000_recv()，并运行 make server 以及（在 xv6 中） nettests。您应该从打印语句中看到 nettests 生成了对以下函数的调用 e1000_transmit.

实现以下功能的一些提示 e1000_transmit:

  • 首先通过读取 E1000_TDT 控制寄存器，向 E1000 查询其期望接收下一个数据包的 TX 环索引。
  • 然后检查环是否溢出。如果 E1000_TXD_STAT_DD 未在 E1000_TDT索引的描述符中设置，说明 E1000 尚未完成相应的上一次发送请求，因此返回错误。
  • 否则，使用 mbuffree() 释放从该描述符传输的最后一个 mbuf（如果有的话）。
  • 然后填写描述符。 m->head 指向数据包内容在内存中的位置，以及 m->len 是数据包长度。设置必要的 cmd 标志（参见 E1000 手册第 3.3 节），并保存指向该 mbuf 的指针以便稍后释放。
  • 最后，将 E1000_TDT 取模 TX_RING_SIZE.
  • 如果 e1000_transmit() 成功将 mbuf 添加到环形缓冲区后，返回 0。若失败（例如，没有可用的描述符来传输该 mbuf），则返回 -1，以便调用方知道需要释放该 mbuf。

实现以下功能的一些提示 e1000_recv:

  • 首先通过读取 E1000_RDT 控制寄存器并加一后对 RX_RING_SIZE.
  • 然后通过检查 E1000_RXD_STAT_DD 位于描述符的 status 部分中来确认是否有新数据包可用。若没有，则停止。
  • 否则，更新 mbuf 的 m->len 为描述符中报告的长度。使用以下方法将 mbuf 传递给网络栈 net_rx().
  • 然后使用以下方法分配一个新的 mbuf mbufalloc() 以替换刚刚交给 net_rx()的那个。将其数据指针（m->head）写入描述符。将描述符的状态位清零。
  • 最后，将 E1000_RDT 寄存器更新为最后处理的环描述符的索引。
  • e1000_init() 会用 mbuf 初始化 RX 环，建议查看其实现方式，并可参考其中的代码。
  • 在某些情况下，累计到达的数据包总数可能会超过环的大小（16）；请确保你的代码能够正确处理这种情况。

你需要使用锁，以应对 xv6 可能从多个进程同时使用 E1000，或在中断到来时内核线程正在使用 E1000 的情况。

以下挑战练习的部分收益只能在真实的高性能硬件（即基于 x86 的计算机）上衡量或测试。

  • 在本实验中，网络栈使用中断处理入站数据包，但不处理出站数据包。一种更复杂的策略是在软件中对出站数据包进行排队，并在任意时刻只向 NIC 提供有限数量的数据包。随后可依赖 TX 中断来补充发送环。使用此技术，可以对不同类型的出站流量进行优先级排序。
  • 所提供的网络代码仅部分支持 ARP。请实现完整的 ARP 缓存 并将其接入 net_tx_eth().
  • E1000 支持多个 RX 和 TX 环。请配置 E1000 为每个核心提供一对收发环，并修改你的网络栈以支持多个环。这样做有望提升网络栈可支持的吞吐量，同时减少锁竞争。 ，但难以测试或衡量
  • sockrecvudp() 使用单链表查找目标套接字，效率较低。请尝试改用哈希表和 RCU 来提升性能。 ，但严肃的实现难以测试或衡量
  • ICMP 可提供网络流失败的通知。请检测这些通知，并通过套接字系统调用接口将其作为错误传播出去。
  • E1000 支持多种无状态硬件卸载功能，包括校验和计算、RSC 和 GRO。请使用其中一种或多种卸载功能来提升网络栈的吞吐量。 ，但难以测试/衡量
  • 本实验中的网络协议栈容易出现接收活锁问题。请结合课堂内容及阅读材料，设计并实现一种解决方案来修复该问题。 ，但难以测试。
  • 为 xv6 实现一个 UDP 服务器。
  • 实现一个最小化的 TCP 协议栈并下载一个网页。
