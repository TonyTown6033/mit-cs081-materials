实验：文件系统

在本实验中，你将为 xv6 文件系统添加大文件和符号链接支持。

在编写代码之前，你应该阅读 xv6 书 并研究相应的代码。

获取本实验的 xv6 源代码并切换到 util branch: 

  $ git fetch
  $ git checkout fs
  $ make clean

大文件

在本次作业中，你将增大 xv6 文件的最大大小。目前，xv6 文件被限制为 268 个块，即 268*BSIZE 字节（在 xv6 中，BSIZE 为 1024）。这一限制源于以下事实：xv6 的 inode 包含 12 个"直接"块号和一个"单级间接"块号，后者指向一个最多可存储 256 个块号的块，因此总计为 12+256=268 个块。

该 bigfile 命令会创建尽可能长的文件，并报告该文件的大小： 

$ bigfile
..
wrote 268 blocks
bigfile: file is too small
$
测试失败是因为 bigfile 期望能够创建一个包含 65803 个块的文件，但未经修改的 xv6 将文件限制为 268 个块。

你需要修改 xv6 文件系统代码，以支持每个 inode 中包含一个"二级间接"块，该块存有 256 个一级间接块的地址，每个一级间接块最多可包含 256 个数据块地址。最终，一个文件最多可由 65803 个块组成，即 256*256+256+11 个块（是 11 而非 12，因为我们将牺牲一个直接块编号来存放二级间接块）。

准备工作

该 mkfs 程序创建 xv6 文件系统磁盘镜像，并决定文件系统的总块数；该大小由 FSSIZE 在 kernel/param.h控制。你会看到 FSSIZE 在本实验的代码仓库中被设置为 200,000 个块。你应该在 mkfs/mkfs 的 make 输出中看到以下内容： 
nmeta 71 (boot, super, log blocks 31, inode blocks 13, bitmap blocks 25) blocks 199929 total 200000
这一行描述了 mkfs/mkfs 所构建的文件系统：它包含 71 个元数据块（用于描述文件系统的块）和 199,929 个数据块，共计 200,000 个块。

注意， make qemu 会构建一个新的 fs.img，并将旧的保存在 fs.img.bk中。如果你希望使用现有的 fs.img 而非重新构建，请运行 make qemu-fs.

重点内容

`struct dinode` in `kernel/fs.h`. An inode contains a `nlink` field that counts the number of directory entries that refer to this inode, in order to recognize when the on-disk inode and its data blocks should be freed. You should add a `uint` `symlink` field to `struct dinode` to track how many symbolic links refer to this inode. 磁盘上 inode 的格式由 `kernel/fs.h` 中的 `struct dinode` 定义。inode 包含一个 `nlink` 字段，用于统计指向该 inode 的目录项数量，以便判断何时应释放磁盘上的 inode 及其数据块。你需要在 `struct dinode` 中添加一个 `uint` 类型的 `symlink` 字段，用于记录有多少符号链接指向该 inode。 struct dinode 在 fs.h。您尤其对以下内容感兴趣 NDIRECT, NINDIRECT, MAXFILE，以及 addrs[] 的元素 struct dinode请查看 xv6 教材中的图 10.3，了解标准 xv6 inode 的结构图。

在磁盘上查找文件数据的代码位于 bmap() 在 fs.c。看一下它，确保你理解它在做什么。 bmap() 在读取和写入文件时都会调用该函数。写入时， bmap() 根据需要分配新块以存储文件内容，并在需要时分配一个间接块以存储块地址。

bmap() 处理两种类型的块编号。 bn 参数是"逻辑块号"——文件内的块号，相对于文件起始位置。其中的块号在 ip->addrs[]，以及传递给 bread()，是磁盘块编号。你可以将 bmap() 视为将文件的逻辑块编号映射到磁盘块编号。

你的任务

修改 bmap() ，使其在直接块和一级间接块的基础上，额外实现一个二级间接块。为了给新的二级间接块腾出空间，你需要将直接块数量从 12 减少到 11；不允许更改磁盘上 inode 的大小。 ip->addrs[] 的前 11 个元素应为直接块；第 12 个应为一级间接块（与当前相同）；第 13 个应为你新增的二级间接块。当 bigfile 写入 65803 个块，且 usertests -q 运行成功时，本练习即告完成： 
$ bigfile
..................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................................
wrote 65803 blocks
done; ok
$ usertests -q
...
ALL TESTS PASSED
$

bigfile 运行至少需要一分半钟。

Hints:

  • 请确保你理解 bmap()。画出以下各部分之间关系的示意图： ip->addrs[]、间接块、二级间接块及其所指向的一级间接块，以及数据块。请确保你理解为什么添加一个二级间接块会使最大文件大小增加 256×256 个块（实际上是减 1，因为你需要将直接块数量减少一个）。
  • 思考如何使用逻辑块号对二级间接块及其所指向的间接块进行索引。
  • 如果你更改了 NDIRECT的定义，你可能还需要更改 addrs[] 在 struct inode 在 file.h的声明。请确保 struct inode 和 struct dinode 在其 addrs[] 数组中拥有相同数量的元素。
  • 如果你更改了 NDIRECT，请确保创建一个新的 fs.img，因为 mkfs 使用 NDIRECT 来构建文件系统。
  • 如果你的文件系统进入损坏状态（例如因崩溃导致），请删除 fs.img （请在 Unix 下执行此操作，而非在 xv6 中）。 make 将为你构建一个新的干净文件系统镜像。
  • 不要忘记 brelse() 你所操作的每个块 bread().
  • 你应该仅在需要时分配间接块和二级间接块，就像原始的 bmap().
  • 确保 itrunc 释放文件的所有块，包括二级间接块。
  • usertests 运行时间比之前的实验更长，因为在本实验中 FSSIZE 更大，且大文件也更大。

符号链接

在本练习中，你将为 xv6 添加符号链接。符号链接（或软链接）通过路径名引用所链接的文件或目录；当打开符号链接时，内核会查找所链接的名称。符号链接与硬链接类似，但硬链接仅限于指向同一磁盘上的文件，不能引用目录，且绑定到特定的目标 i 节点，而符号链接则引用目标名称在当时所对应的内容（如果存在的话）。实现此系统调用是理解路径名查找机制的良好练习。

在本实验中，你无需处理指向目录的符号链接；唯一需要知道如何跟随符号链接的系统调用是 open().

你的任务

你将实现 symlink(char *target, char *path) 系统调用，该调用在 path 处创建一个新的符号链接，指向 target 所命名的文件。更多信息请参阅 man 手册页 symlink。如需测试，请将 symlinktest 添加到 Makefile 并运行。当测试产生如下输出时（包括 usertests 通过），你的解决方案即为完成。 

$ symlinktest
Start: test symlinks
test symlinks: ok
Start: test concurrent symlinks
test concurrent symlinks: ok
$ usertests -q
...
ALL TESTS PASSED
$

Hints:

  • 首先，为 symlink 创建一个新的系统调用编号，在 user/usys.pl、user/user.h 中添加相应条目，并在 kernel/sysfile.c 中实现一个空的 sys_symlink。
  • 在 kernel/stat.h 中添加一种新的文件类型（T_SYMLINK）以表示符号链接。
  • 在 kernel/fcntl.h 中添加一个新标志（O_NOFOLLOW），该标志可与 open 系统调用一起使用。注意，传递给 open 的标志通过按位 OR 运算符组合，因此你的新标志不应与任何已有标志重叠。将 user/symlinktest.c 添加到 Makefile 后，这将使你能够顺利编译该文件。
  • 实现 symlink(target, path) 系统调用，在 path 处创建一个指向 target 的新符号链接。注意，target 无需存在即可使该系统调用成功。你需要选择一个位置来存储符号链接的目标路径，例如存储在 inode 的数据块中。 symlink 应返回一个整数，表示成功（0）或失败（-1），类似于 link 和 unlink.
  • 修改 open 系统调用，以处理路径指向符号链接的情况。如果文件不存在， open 必须失败。当进程在 O_NOFOLLOW 的 flags 参数中指定 open, open 时，应打开符号链接本身（而不跟随符号链接）。
  • 如果链接指向的文件也是符号链接，则必须递归跟随，直到到达非链接文件为止。如果链接形成环路，必须返回错误码。可以通过在链接深度达到某一阈值（例如 10）时返回错误码来近似实现此要求。
  • 其他系统调用（例如 link 和 unlink）不得跟随符号链接；这些系统调用直接操作符号链接本身。
