实验：系统调用

在上一个实验中，你使用系统调用编写了一些实用程序。在本实验中，你将向 xv6 添加一个新的系统调用，这将帮助你理解系统调用的工作原理，并让你接触 xv6 内核的一些内部机制。你将在后续实验中添加更多系统调用。

沙箱化一个命令

在本次作业中，你将对进程进行"沙盒化"处理，以限制其可以发起的系统调用。例如，可以对进程进行沙盒化以禁止其打开文件。你将创建一个新的 interpose 该系统调用将指定内核应拒绝来自调用进程的哪些系统调用。 interpose 应接受两个参数：一个整数掩码和一个路径。掩码的二进制位指定要拒绝哪些系统调用。第二个参数将在下一个作业中使用，在本次作业中它始终为 "-"。例如，为了让一个进程阻止自己使用 open 系统调用，它应该调用 interpose(1 << SYS_open, "-")，其中 SYS_open 是来自 kernel/syscall.h。你的实现应确保掩码能够被 fork 的子进程继承，以便子进程继承父进程的限制。
我们已经为您提供了一个 user/sandbox.c 用户程序执行 fork，调用 interpose() 在子进程中，然后在子进程中执行（exec）一个程序。当你完成实现后 interpose()，你应该会看到如下输出： 
$ sandbox 32768 - cat README
cat: cannot open README
$

在这个例子中， cat README 是被沙箱化的命令。32768 是要拒绝的系统调用的掩码；在此示例中，它是 1<<SYS_open。如果你的解答正确，你应该看到 "cat: cannot open README"。

如果您通过以下测试，您的解决方案将获得满分： grade-lab-syscall sandbox_mask: 

$ ./grade-lab-syscall sandbox_mask
== Test sandbox_mask == sandbox_mask: OK (1.5s)

一些提示：

  • 添加 $U/_sandbox 到 Makefile 中的 UPROGS

  • 运行 make qemu 你将看到编译器无法编译 user/sandbox.c，因为 interpose 系统调用的用户态存根尚不存在：请为 interpose 至 user/user.h添加一个原型，为 user/usys.pl添加一个存根，并为 kernel/syscall.h添加一个系统调用号。Makefile 会调用 perl 脚本 user/usys.pl，该脚本生成 user/usys.S，即实际的系统调用存根，这些存根使用 RISC-V ecall 指令切换到内核。修复编译问题后，在 sandbox 32768 - cat README xv6 shell 中运行；该命令将会失败，因为你尚未在内核中实现该系统调用。

  • 添加一个 sys_interpose() 函数，位于 kernel/sysproc.c 通过将 mask 参数记录在 proc 结构体（参见 kernel/proc.h）。用于从用户态获取系统调用参数的函数位于 kernel/syscall.c，你可以在其中看到它们的使用示例，位于 kernel/sysproc.c. 将你的新 sys_interpose 到 syscalls 数组中 kernel/syscall.c.

  • 修改 kfork() （参见 kernel/proc.c）将掩码从父进程复制到子进程。

  • 修改 syscall() 函数，位于 kernel/syscall.c 以检查是否必须拒绝该系统调用。

攻击 xv6

xv6 内核将用户程序彼此隔离，并将内核与用户程序隔离。正如你在上述作业中所看到的，应用程序无法直接调用内核或其他用户程序中的函数；所有交互只能通过系统调用进行。然而，如果内核在实现某个系统调用时存在漏洞，攻击者就可能利用该漏洞打破隔离边界。为了了解漏洞是如何被利用的，我们在 xv6 中故意引入了一个漏洞，你的目标是利用该漏洞从另一个进程中窃取一个秘密。

该漏洞在于，对 memset(mem, 0, sz) 在 uvmalloc() 在 kernel/vm.c 的调用（用于清零新分配的页面）在编译本实验时被省略了。类似地，在编译 kernel/kalloc.c 时，使用 memset 向空闲页写入垃圾数据的两行代码也被省略了。省略这 3 行代码（均以 ifndef LAB_SYSCALL标记）的最终效果是：新分配的内存会保留其上次使用时的内容。因此，调用 sbrk() 分配内存的应用程序可能会收到包含历史数据的页面。尽管删除了这 3 行代码，xv6 大部分功能仍能正常运行，甚至能通过大多数 usertests.

user/secret.c 将一个秘密字符串写入其内存后退出（从而释放其内存）。你的目标是在 user/attack.c 中添加若干行代码，以找到 secret.c 之前某次执行写入内存中的秘密，并将该秘密单独打印在一行上。

你的 attack.c 必须与未修改的 xv6 和未修改的 secret.c配合使用。你可以做任何更改来辅助实验和调试，但在最终测试和提交前必须还原这些更改。

该 secret 程序将密钥作为参数。你可以通过运行来测试你的 attack 程序，方法是运行 secret 并传入某个参数，然后运行 attack，并查看 attack 是否恰好打印出传递给 secret的参数。以下是一次成功运行的示例： 
$ secret xyzzy
$ attack
xyzzy
$

根据你的攻击实现方式，你可能需要再次运行 attack 才能找到密钥。评分程序会运行 attack 两次以防万一，只要其中一次能输出密钥即视为通过。

在 xv6 外部，你可以使用 ./grade-lab-syscall attack，或 make grade，以查看你的攻击是否通过我们的测试。测试生成的秘密字符串保证只包含数字以及大小写字母。

与此示例类似，不直接影响正确性的漏洞有时也可被利用来破坏安全性。严谨的编程和大量的测试可以减少漏洞数量，但无法保证完全消除。xv6 过去曾存在漏洞，也可能仍有尚未发现的错误。相比 xv6，真实内核的代码量大得多，此类漏洞更是由来已久。例如，请参阅公开的 Linux 漏洞 和 如何报告漏洞.
