睡觉

本练习使您熟悉在 xv6 上编写用户程序以及 pause 系统调用。

实现用户级 sleep xv6 的程序，类似于 UNIX sleep 命令。你的 sleep 应暂停用户指定的刻度数。时钟周期是 xv6 内核定义的时间概念，即定时器芯片两次中断之间的时间。您的解决方案应该在文件中 user/sleep.c.

一些提示：

  • 在开始编码之前，请阅读本书的第 1 章 xv6 书.
  • 将您的代码放入 user/sleep.c。看看其他一些程序 user/ （例如， user/echo.c, user/grep.c, 和 user/rm.c）来查看命令行参数如何传递给程序。
  • 添加您的 sleep 编程到 UPROGS 在 Makefile 中；一旦你这样做了， make qemu 将编译您的程序，您将能够从 xv6 shell 运行它。
  • 如果用户忘记传递参数，sleep 应该打印一条错误消息。
  • 命令行参数作为字符串传递；您可以使用将其转换为整数 atoi （参见 user/ulib.c）。
  • 使用系统调用 pause().
  • 参见 kernel/sysproc.c 对于实现以下功能的 xv6 内核代码 pause() 系统调用（寻找 sys_pause), user/user.h 对于 C 的定义 pause() 可从用户程序调用，以及 user/usys.S 对于从用户代码跳转到内核的汇编代码 pause().
  • 看看克尼根和里奇的书 C语言程序设计（第二版） (K&R) 了解 C.

从 xv6 shell 运行程序： 

      $ make qemu
      ...
      init: starting sh
      $ sleep 10
      (nothing happens for a little while)
      $

您的程序在运行时应该暂停，如上所示。运行 make grade 在命令行（qemu 之外）中查看您是否通过睡眠测试。

请注意 make grade 运行所有测试，包括以下任务的测试。如果您想运行一项任务的成绩测试，请输入： 

     $ ./grade-lab-util sleep
这将运行与“睡眠”匹配的等级测试。或者，您可以输入： 
     $ make GRADEFLAGS=sleep grade
其作用相同。

内存转储

本练习将让您更多地练习使用 C 指针。在开始之前，请阅读 Kernighan 和 Ritchie (K&R) 所著的《C 编程语言（第二版）》中的第 5.1 节（指针和地址）到 5.6（指针数组）和 6.4（结构体指针）。

看看 user/memdump.c。你的工作是实现该功能 memdump(char *fmt, char *data). memdump()的目的是以 fmt 参数描述的格式打印 data 指向的内存内容。格式是 C 字符串。字符串的每个字符指示如何打印数据的连续部分。因此，例如，具有多个字段的 C 结构体可以使用包含多个字符的格式字符串进行打印。

您的 memdump() 应处理以下格式字符：

  • i：将数据的接下来 4 个字节打印为 32 位整数（十进制）。
  • p：将数据的接下来 8 个字节打印为 64 位整数（以十六进制表示）。
  • h：将数据的接下来 2 个字节打印为 16 位整数（十进制）。
  • c：将数据的下一个 1 字节打印为 8 位 ASCII 字符。
  • s：接下来的 8 个字节的数据包含一个指向 C 字符串的 64 位指针；打印字符串。
  • S：其余数据包含以 null 结尾的 C 字符串的字节；打印字符串。

随意使用C printf() 在你的 memdump().

的 memdump 程序，如果不带参数执行，则调用 memdump() 一些示例格式字符串和数据。如果 memdump() 如果正确实现，输出将是：

找到

本练习探讨路径名和目录，以及系统调用 open、read 和 fstat。

为 xv6 编写一个简单版本的 UNIX 查找程序：查找目录树中具有特定名称的所有文件。您的解决方案应该在文件中 user/find.c.

一些提示：

  • 查看 user/ls.c 以了解如何读取目录。
  • 使用递归允许 find 深入到子目录。
  • 不要递归成“.”和 ”..”。
  • 每次调用时 make qemu，它将构建一个新的 fs.img，删除先前运行中创建的文件。如果您想使用以前使用过的文件系统启动 qemu make qemu-fs.
  • 您需要使用 C 字符串。看一下 K&R（C 书），例如第 5.5 节。
  • Note that == does not compare strings as in Python. Use strcmp() instead.
  • 将程序添加到 UPROGS 在 Makefile 中。

您的解决方案应产生以下输出（当文件系统包含文件 b, a/b 和 a/aa/b): 

    $ make qemu
    ...
    init: starting sh
    $ echo > b
    $ mkdir a
    $ echo > a/b
    $ mkdir a/aa
    $ echo > a/aa/b
    $ find . b
    ./b
    ./a/b
    ./a/aa/b
    $

运行 make grade 看看我们的测试是怎么想的。

执行

本练习涉及系统调用 fork、exec 和 wait。

添加一个“-exec 指令” 到 find，执行程序“cmd file“对于每个文件 f 那个 find 查找，而不是打印匹配的文件名。

以下示例说明了 find -exec 行为： 
    $ find . wc -exec echo hi
    hi ./wc
    $
注意，这里的命令是“echo hi”，文件是“./wc”，使得命令“echo hi ./wc”，输出“hi ./wc”。

一些提示：

  • 使用 fork 和 exec 对每个文件调用该命令。使用 wait 在父进程中等待子进程完成命令。
  • kernel/param.h 声明了 MAXARG，如果您需要声明 argv 数组，这可能很有用。

要测试您的 find 解决方案，请运行 shell 脚本 findtest.sh。您的解决方案应产生以下输出： 

  $ make qemu
  ...
  init: starting sh
  $ sh < findtest.sh
$ echo DONE
$ $ $ $ $ hello
hello
hello
$ $
输出有很多 $ 因为 xv6 shell 没有意识到它正在处理来自文件而不是来自控制台的命令，并打印 $ 对于文件中的每个命令。
