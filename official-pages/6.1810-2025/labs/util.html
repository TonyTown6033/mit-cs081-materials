sleep

本练习帮助你熟悉如何在 xv6 上编写用户程序，以及 pause 系统调用。

为 xv6 实现一个用户态的 sleep 程序，仿照 UNIX sleep 命令的方式。你的 sleep 应暂停用户指定的 tick 数。tick 是 xv6 内核定义的时间单位，即计时器芯片两次中断之间的时间间隔。你的解答应位于文件 user/sleep.c.

一些提示：

  • 开始编写代码前，请阅读 xv6 书.
  • 将你的代码放入 user/sleep.c。查看 user/ （例如， user/echo.c, user/grep.c以及 user/rm.c）中的一些其他程序，了解命令行参数是如何传递给程序的。
  • 将你的 sleep 程序添加到 UPROGS 的 Makefile 中；完成后， make qemu 将编译你的程序，你就可以在 xv6 shell 中运行它了。
  • 如果用户忘记传递参数，sleep 应打印一条错误信息。
  • 命令行参数以字符串形式传入；你可以使用 atoi （参见 user/ulib.c）将其转换为整数。
  • 使用系统调用 pause().
  • 参见 kernel/sysproc.c 用于实现该功能的 xv6 内核代码 pause() 系统调用（查找 sys_pause), user/user.h 的 C 定义 pause() 可从用户程序调用，以及 user/usys.S 用于从用户代码跳转到内核的汇编代码，用于 pause().
  • 参阅 Kernighan 和 Ritchie 的著作 《C 程序设计语言》（第二版） （K&R）以学习 C 语言。

在 xv6 shell 中运行该程序： 

      $ make qemu
      ...
      init: starting sh
      $ sleep 10
      (nothing happens for a little while)
      $

如上所示运行时，程序应暂停。运行 make grade 在命令行中（在 qemu 外部）查看是否通过 sleep 测试。

注意， make grade 运行所有测试，包括以下任务的测试。如果只想运行某一任务的评分测试，请输入： 

     $ ./grade-lab-util sleep
这将运行与 "sleep" 匹配的评分测试。或者，你也可以输入： 
     $ make GRADEFLAGS=sleep grade
其功能相同。

sixfive

在本练习中，你将使用系统调用 open 和 read、C 字符串以及 C 语言文本文件处理。

对于每个输入文件， sixfive 必须打印文件中所有能被 5 或 6 整除的数字。数字是由字符串 " -\r\t\n./," 中的字符分隔的十进制数字序列。因此，对于 "xv6" 中的 6，sixfive 不应打印该 6，但例如 "/6," 中的 6 则应打印。

以下示例说明了 sixfive 的行为： 
    $ sixfive sixfive.txt
    5
    100
    18
    6
    $

一些提示：

  • 每次读取输入文件中的一个字符
  • 你可以使用以下方法判断某个字符是否匹配任意分隔符 strchr （参见 user/ulib.c）将其转换为整数。
  • 文件的开头和结尾视为隐式分隔符。

memdump

本练习将帮助你进一步练习使用 C 指针。开始之前，请阅读 Kernighan 和 Ritchie（K&R）所著《C 程序设计语言（第二版）》中的 5.1 节（指针与地址）至 5.6 节（指针数组）以及 6.4 节（指向结构的指针）。

请参阅 user/memdump.c。你的任务是实现该函数 memdump(char *fmt, char *data). memdump()的作用是按照 fmt 参数所描述的格式，打印 data 所指向的内存内容。格式是一个 C 字符串。字符串中的每个字符指示如何打印数据的连续部分。因此，举例来说，一个包含多个字段的 C 结构体可以用一个包含多个字符的格式字符串来打印。

您的 memdump() 应处理以下格式字符：

  • i：以十进制形式打印数据的后续 4 个字节，作为 32 位整数。
  • p：以十六进制形式打印数据中接下来的 8 个字节，作为一个 64 位整数。
  • h：以十进制打印数据的后续 2 个字节，作为 16 位整数。
  • c：将数据的下一个 1 字节以 8 位 ASCII 字符形式打印。
  • s：数据的接下来 8 个字节包含一个指向 C 字符串的 64 位指针；打印该字符串。
  • S：其余数据包含一个以空字符结尾的 C 字符串的字节；打印该字符串。

可以随意使用 C 的 printf() 在你的 memdump().

该 memdump 程序，若不带任何参数执行，则调用 memdump() 以及一些示例格式字符串和数据。如果 memdump() 已正确实现，输出将为： 

$ memdump

Example 2:
a string
Example 3:
another
Example 4:
BD0

xyzzy
Example 5:
hello

d

示例 4 输出的第一行，你得到的十六进制地址可能与示例不同。

如果 memdump 程序在调用时带有参数，它将从标准输入读取直到文件结束，然后以格式字符串和输入数据为参数调用 memdump() 因此，一旦 memdump() 实现完成：

find

本练习探索路径名与目录，以及系统调用 open、read 和 fstat。

为 xv6 编写一个简化版的 UNIX find 程序：在目录树中查找所有具有指定名称的文件。你的解答应放在文件 user/find.c.

一些提示：

  • 参阅 user/ls.c，了解如何读取目录。
  • 使用递归，使 find 能够进入子目录。
  • 不要递归进入 "." 和 ".."。
  • 每次你调用 make qemu，它都会构建一个新的 fs.img，并删除上一次运行中创建的文件。如果你希望使用上一次的文件系统启动 qemu make qemu-fs.
  • 你需要使用 C 字符串。可参阅 K&R（C 语言教材），例如第 5.5 节。
  • 注意，== 不像在 Python 中那样比较字符串，请改用 strcmp()。
  • 将该程序添加到 UPROGS 中的 Makefile 里。

你的解答应产生如下输出（当文件系统包含以下文件时 b, a/b 和 a/aa/b): 

    $ make qemu
    ...
    init: starting sh
    $ echo > b
    $ mkdir a
    $ echo > a/b
    $ mkdir a/aa
    $ echo > a/aa/b
    $ find . b
    ./b
    ./a/b
    ./a/aa/b
    $

运行 make grade 以查看测试的具体要求。

exec

本练习涉及系统调用 fork、exec 和 wait。

添加一个 "-exec cmd" 到 find，对每个文件执行程序 "cmd file" 对每个文件 f 满足条件的 find finds 找到的，而不是打印匹配的文件名。

以下示例说明了 find -exec 的行为： 
    $ find . wc -exec echo hi
    hi ./wc
    $
注意，此处的命令为 "echo hi"，文件为 "./wc"，因此完整命令为 "echo hi ./wc"，输出结果为 "hi ./wc"。

一些提示：

  • 使用 fork 和 exec 以对每个文件调用该命令。使用 wait 在父进程中等待子进程完成该命令。
  • kernel/param.h 中声明了 MAXARG，如果需要声明 argv 数组，该常量可能会有用。

要测试你的 find 解题方案，请运行 shell 脚本 findtest.sh。你的解题方案应产生如下输出： 

  $ make qemu
  ...
  init: starting sh
  $ sh < findtest.sh
$ echo DONE
$ $ $ $ $ hello
hello
hello
$ $
输出中之所以有许多 $，是因为 xv6 shell 没有意识到自己正在处理的是来自文件的命令，而不是来自控制台的命令，因此会为文件中的每条命令都打印一个 $。
