实验：xv6 的写时复制 fork

虚拟内存提供了一层间接性：内核可以通过将 PTE 标记为无效或只读来拦截内存引用，从而触发页面错误，并可以通过修改 PTE 来改变地址的含义。计算机系统中有句名言：任何系统问题都可以通过增加一层间接性来解决。本实验探索一个具体示例：写时复制 fork。

要开始本实验，请切换到 cow 分支： 

$ git fetch
$ git checkout cow
$ make clean

问题描述

xv6 中的 fork() 系统调用会将父进程的全部用户态内存复制到子进程中。如果父进程占用内存较大，复制过程可能耗费大量时间。更糟糕的是，这些工作往往大部分都是徒劳的：子进程在 fork() 之后通常紧接着调用 exec()，这会丢弃已复制的内存，而其中大部分根本未被使用。另一方面，如果父子进程都使用某个已复制的页面，且其中一方或双方对其进行写操作，那么该复制才是真正必要的。

解决方案

实现写时复制（COW）fork() 的目标是：将物理内存页的分配与复制推迟到真正需要时才执行（如果确实需要的话）。

COW fork() 仅为子进程创建一个页表，其中用户内存的 PTE 指向父进程的物理页。COW fork() 将父子进程中所有用户态 PTE 均标记为只读。当任一进程尝试写入这些 COW 页时，CPU 将触发页面错误。内核的页面错误处理程序检测到该情况后，为发生错误的进程分配一个新的物理内存页，将原始页内容复制到新页中，并修改该进程中对应的 PTE 使其指向新页，同时将该 PTE 标记为可写。页面错误处理程序返回后，用户进程即可对其私有的页面副本执行写操作。

COW fork() 使得释放实现用户内存的物理页变得稍微复杂一些。同一个物理页可能被多个进程的页表所引用，只有当最后一个引用消失时才应将其释放。在 xv6 这样简单的内核中，这种记录管理尚且直观，但在生产级内核中则难以做到正确；例如，请参见 不停打补丁，直到写时复制实验完成.

实现写时复制 fork

你的任务是在 xv6 内核中实现写时复制 fork。如果你修改后的内核能够成功执行 cowtest 和 'usertests -q' 程序，则表示实验完成。

为了帮助你测试实现，我们提供了一个名为 cowtest 的 xv6 程序（源码位于 user/cowtest.c）。cowtest 会运行多项测试，但即使是第一项测试在未修改的 xv6 上也会失败。因此，初始情况下你会看到： 

$ cowtest
simple: fork() failed
$
"simple" 测试会分配超过一半的可用物理内存，然后调用 fork()。由于没有足够的空闲物理内存为子进程提供父进程内存的完整副本，fork 会失败。

完成后，你的内核应能通过 cowtest 和 usertests -q 中的所有测试。即： 

$ cowtest
simple: ok
simple: ok
three: ok
three: ok
three: ok
file: ok
forkfork: ok
ALL COW TESTS PASSED
$ usertests -q
...
ALL TESTS PASSED
$

以下是一个合理的实现思路。

  1. 修改 uvmcopy()，将父进程的物理页映射到子进程，而不是分配新页。清除 PTE_W 在子进程和父进程中，对设置了 PTE_W 的页所对应的页表项（PTE）中的该标志位。
  2. 修改 vmfault()，使其能够识别缺页故障。当对一个原本可写的 COW 页发生写缺页故障时，使用 kalloc() 分配新页，将旧页内容复制到新页，并将新页安装到页表项（PTE）中，同时设置 PTE_W 原本为只读的页（未映射为 PTE_W，例如文本段中的页面）应保持只读状态，并在父进程和子进程之间共享；试图写入此类页面的进程应被终止。
  3. 确保每个物理页在最后一个指向它的 PTE 引用消失时被释放——但不能提前释放。一种好的做法是，为每个物理页维护一个"引用计数"，记录有多少用户页表引用了该页。当 kalloc() 在分配页面时将其引用计数初始化为 1。当 fork 导致子进程共享该页面时，增加页面的引用计数；每当任何进程从其页表中释放该页面时，减少页面的引用计数。 kfree() 只有当页面的引用计数为零时，才应将该页面放回空闲列表。可以将这些计数保存在一个固定大小的整数数组中。你需要设计一种方案来确定数组的索引方式及其大小。例如，可以用页面的物理地址除以 4096 作为数组索引，并将数组的元素数量设置为等于由 kinit() 在 kalloc.c 中。请随意修改 kalloc.c（例如， kalloc() 和 kfree()）来维护引用计数。
  4. 修改 `copyout()`，使其在遇到写时复制页面时采用与处理页错误相同的方案。

一些提示：

  • 为每个 PTE 记录其是否为写时复制映射，这样的机制可能很有用。你可以使用 RISC-V PTE 中的 RSW（reserved for software）位来实现这一点。
  • usertests -q 探索以下场景 cowtest 不会测试，因此请不要忘记检查两者的所有测试是否都能通过。
  • `kernel/riscv.h`. 页表标志的一些有用宏和定义位于 `kernel/riscv.h` 的末尾。 kernel/riscv.h.
  • 如果发生写时复制页面错误且没有空闲内存，该进程应被终止。
