实验指南

作业难度

每项作业均标注了其难度等级：

  • 简单：不足一小时。这类练习通常是后续练习的热身题。

  • 中等：1-2 小时。

  • 困难：超过 2 小时。这类练习通常不需要编写大量代码，但代码的正确实现颇具技巧性。

以上时间仅为我们的粗略预估。对于部分选做作业，我们没有参考答案，难度评级只是大致猜测。如果你发现自己在某项作业上花费的时间超出预期，请在 Piazza 上留言或前来参加答疑课。

总体而言，这些练习所需的代码量不多（从数十行到数百行不等），但代码在概念上较为复杂，且细节往往至关重要。因此，请务必完成实验的指定阅读材料，通读相关文件，并查阅参考文档（RISC-V 手册等均可在 参考资料页）在你编写任何代码之前。以小步骤实现你的解决方案（作业通常会建议如何分解问题），并在继续下一步之前测试每个步骤是否正常工作。

警告：不要在实验截止日期前一晚才开始做；将工作分散在多天内完成效率更高。操作系统内核中的 bug 往往令人困惑，可能需要大量思考和仔细调试才能理解并修复。

调试技巧

以下是一些调试技巧：

  • 确保你理解 C 语言和指针。Kernighan 与 Ritchie 所著的《C 程序设计语言（第二版）》是对 C 语言的精炼描述。请参阅以下示例 代码 并确保你理解为什么它会产生这样的结果。

    有几种常见的指针惯用法特别值得记住：

    • 如果 int *p = (int*)100，然后 (int)p + 1 和 (int)(p + 1) 是不同的数字：第一个是 101 但第二个是 104。在第二种情况下，将整数加到指针时，整数会隐式地乘以指针所指向对象的大小。
    • p[i] 被定义为等同于 *(p+i)，表示 p 所指向内存中第 i 个对象。上述加法规则确保当对象大小超过一个字节时，该定义仍然有效。
    • &p[i] 等同于 (p+i)，得到 p 所指向内存中第 i 个对象的地址。

    尽管大多数 C 程序无需在指针与整数之间进行类型转换，但操作系统中这种情况十分常见。每当看到涉及内存地址的加法运算时，请思考它是整数加法还是指针加法，并确认被加的值是否经过了适当的乘法处理。

  • 如果某个练习已部分完成，请通过提交代码来保存进度。若后续出现问题，可回滚至检查点并以更小的步骤继续推进。如需深入了解 Git，请参阅 Git 用户手册，或参考这份 面向计算机科学的 Git 概览.

  • 如果代码未能通过某项测试，请务必弄清原因。插入打印语句，直到理解程序的实际行为为止。

  • 你可能会发现打印语句产生了大量输出需要检索，一种方法是运行 make qemu 内部 script （运行 man script 在您的机器上），它会将所有控制台输出记录到文件中，您可以随后搜索该文件。请不要忘记退出 script.

  • 打印语句通常是足够强大的调试工具，但有时能够单步执行汇编代码或检查栈上的变量也很有帮助。要在 xv6 中使用 gdb，请运行 make make qemu-gdb 在一个窗口中，然后运行 gdb-multiarch （或 riscv64-linux-gnu-gdb 或 riscv64-unknown-elf-gdb）在另一个窗口中（如果您使用的是 Athena，请确保两个窗口位于同一台 Athena 机器上），设置一个断点，然后输入 'c'（继续），xv6 将运行直到命中该断点。参见 GNU 调试器使用指南 以获取有用的 GDB 技巧。（如果您启动 gdb 时看到类似 'warning: File ".../.gdbinit" auto-loading has been declined' 的警告，请按照警告的建议编辑 ~/.gdbinit，添加 "add-auto-load-safe-path..."。）

  • 如果您想查看编译器为 xv6 内核生成的汇编代码，或者想了解某个特定内核地址对应的指令，请查看文件 kernel/kernel.asm，该文件由 Makefile 在编译内核时生成。（Makefile 还会生成 .asm 适用于所有用户程序。）

  • 如果内核引发了意外故障（例如访问了无效的内存地址），它将打印一条包含崩溃时程序计数器（"sepc"）值的错误信息；你可以搜索 kernel.asm 查找包含该程序计数器的函数，或者你可以运行 addr2line -e kernel/kernel pc值 （运行 man addr2line 有关详细信息，请参阅相关说明）。如果需要回溯，请使用 gdb 重新启动：在一个窗口中运行 `make qemu-gdb`，在另一个窗口中运行 gdb（或 `riscv64-linux-gnu-gdb`），在 panic 处设置断点（`b panic`），然后输入 `c`（continue，继续执行）。当内核触发断点时，输入 `bt` 以获取回溯信息。

  • 如果你的内核挂起（例如由于死锁），可以使用 gdb 找出挂起位置。在一个窗口中运行 `make qemu-gdb`，在另一个窗口中运行 gdb（`riscv64-linux-gnu-gdb`），然后输入 `c`（continue）继续执行。当内核出现挂起时，在 qemu-gdb 窗口中按 Ctrl-C，并输入 `bt` 获取回溯信息。

  • qemu 有一个"监视器"，可让你查询模拟机器的状态。你可以通过输入 control-a c 来进入它（"c"代表 console，即控制台）。一个特别有用的监视器命令是 info mem 打印页表。您可能需要使用 cpu 命令来选择哪个核心 info mem 查看，或者你可以使用以下命令启动 qemu make CPUS=1 qemu 使单核心运行。
