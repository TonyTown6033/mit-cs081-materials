实验室指导

作业的难度

每项作业都表明其难度：

  • 简单: 不到一个小时。这些练习通常是后续练习的热身练习。

  • 中等：1-2小时。

  • 硬: 2个多小时。通常，这些练习不需要太多代码，但要正确编写代码却很困难。

这些时间是我们预期的粗略估计。对于某些可选作业，我们没有解决方案，而且难度也只能靠猜测。如果您发现自己在任务上花费的时间比我们预期的要多，请联系广场或在办公时间前来。

一般来说，练习不需要很多行代码（几十到几百行），但代码在概念上很复杂，而且往往细节很重要。因此，请确保完成实验室指定的阅读，通读相关文件，查阅文档（RISC-V 手册等位于 参考页）在编写任何代码之前。分小步实施您的解决方案（作业通常会建议如何分解问题），并在继续下一步之前测试每一步是否有效。

警告：不要在截止日期前一天晚上开始实验；将工作分散到多天进行会更节省时间。操作系统内核中错误的表现可能令人困惑，可能需要大量思考和仔细调试才能理解和修复。

调试技巧

以下是一些调试技巧：

  • 确保您了解 C 和指针。 Kernighan 和 Ritchie 所著的《C 编程语言（第二版）》一书对 C 进行了简洁的描述。看看这个例子 代码 并确保您理解为什么它会产生这样的结果。

    一些常见的指针习惯用法特别值得记住：

    • 如果 int *p = (int*)100，那么 (int)p + 1 和 (int)(p + 1) 是不同的数字：第一个是 101 但第二个是 104。当向指针添加整数时，如第二种情况，整数会隐式乘以指针指向的对象的大小。
    • p[i] 被定义为相同 *(p+i)，引用p指向的内存中的第i个对象。当对象大于一字节时，上述加法规则有助于此定义起作用。
    • &p[i] 是一样的 (p+i)，产生 p 指向的内存中第 i 个对象的地址。

    尽管大多数 C 程序从不需要在指针和整数之间进行转换，但操作系统却经常这样做。每当您看到涉及内存地址的加法时，问问自己这是整数加法还是指针加法，并确保所加的值是否适当地相乘。

  • 如果您的练习部分有效，请通过提交代码来检查进度。如果您稍后破坏了某些内容，则可以回滚到检查点并以较小的步骤前进。要了解有关 Git 的更多信息，请查看 Git 用户手册，或者这个 面向 CS 的 Git 概述.

  • 如果您的代码未通过测试，请确保您了解原因。插入打印语句，直到您了解发生了什么。

  • 您可能会发现您的 print 语句会产生大量您想要搜索的输出；一种方法是运行 make qemu 里面的 script （运行 man script 在您的计算机上），它将所有控制台输出记录到一个文件中，然后您可以搜索该文件。不要忘记退出 script.

  • 打印语句通常是一个足够强大的调试工具，但有时能够单步执行某些汇编代码或检查堆栈上的变量会很有帮助。要将 gdb 与 xv6 一起使用，请运行 make make qemu-gdb 在一个窗口中，运行 gdb-multiarch （或 riscv64-linux-gnu-gdb 或 riscv64-unknown-elf-gdb）在另一个窗口中（如果您使用的是 Athena，请确保这两个窗口位于同一台 Athena 机器上），设置一个断点，后跟“c”（继续），xv6 将运行直到遇到断点。参见 使用 GNU 调试器 获取有用的 GDB 提示。 （如果启动 gdb 并看到“警告：文件“.../.gdbinit”自动加载已被拒绝”形式的警告，请编辑 ~/.gdbinit 以添加“add-auto-load-safe-path...”，如警告所示。）

  • 如果您想查看编译器为 xv6 内核生成的汇编代码或找出特定内核地址处的指令，请参阅该文件 kernel/kernel.asm，Makefile 在编译内核时生成。 （Makefile 还生成 .asm 对于所有用户程序。）

  • 如果内核导致意外故障（例如使用无效的内存地址），它将打印一条错误消息，其中包括崩溃点的程序计数器（“sepc”）；你可以搜索 kernel.asm 找到包含该程序计数器的函数，或者您可以运行 addr2line -e kernel/kernel pc-value （运行 man addr2line 了解详情）。如果您想要回溯，请使用 gdb 重新启动：在一个窗口中运行“make qemu-gdb”，在另一个窗口中运行 gdb（或 riscv64-linux-gnu-gdb），在恐慌中设置断点（“b恐慌”），然后是“c”（继续）。当内核到达断点时，输入“bt”以获取回溯。

  • 如果您的内核挂起（可能是由于死锁），您可以使用 gdb 找出挂起的位置。在一个窗口中运行“make qemu-gdb”，在另一个窗口中运行 gdb (riscv64-linux-gnu-gdb)，然后运行“c”（继续）。当内核出现挂起时，在 qemu-gdb 窗口中按 Ctrl-C 并输入“bt”以获取回溯。

  • qemu 有一个“监视器”，可让您查询模拟计算机的状态。您可以通过输入 control-a c （“c”代表控制台）来获取它。一个特别有用的监视命令是 info mem 打印页表。您可能需要使用 cpu 命令选择哪个核心 info mem 看看，或者你可以启动 qemu make CPUS=1 qemu 导致只有一个核心。
花时间学习上述工具是非常值得的。
