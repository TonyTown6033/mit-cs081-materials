为什么文件系统有用？
  重启后的持久性
  命名和组织
  在程序和用户之间共享
  设备独立性（硬盘、闪存、EBS）

为什么有趣？
  崩溃恢复
  表现
  安全
  API 泛化：管道、设备、/proc、/afs、Plan 9
    因此面向 FS 的应用程序可以处理多种对象
  两个实验室的主题

API 影响设计/实现。
  示例 -- UNIX/Posix/Linux/xv6/&c：
  fd = open("x/y", -);
  写（fd，“abc”，3）；
  链接（“x/y”，“x/z”）； -- 现在文件有两个名称！
  取消链接（“x/y”）；
  写（fd，“def”，3）；
  关闭（fd）；
  // file y/z contains abcdef

UNIX FS API 中可见的高级选择
  对象：文件（与原始磁盘空间、数据库记录相比）
  内容：字节数组（与行/列、BTree）
  size：可以随时追加；未预先分配磁盘空间
  命名：人类可读（相对于对象 ID）
  组织：目录层次结构
  同步：无（无锁定，无版本）
    不会阻止应用程序同时修改！
  这些决定中的每一个在其他一些 FS 中都做出了不同的决定！

API 的一些含义：
  fd 指的是某物
    即使文件名更改也会保留
    或者如果文件在打开时被删除！
  一个文件可以有多个“硬”链接
    即出现在多个目录中
    这些事件没有一件是特别的
    so 文件必须将信息存储在目录以外的位置
  thus:
    FS 将文件信息记录在磁盘上的“inode”中
    FS 指的是带有 i 号的 inode
    inode 必须有链接计数（告诉我们何时释放）
    inode 必须有打开 FD 的计数
    inode 释放推迟到最后一个链接和 FD 消失为止

FS软件层

数据在磁盘上意味着数据是持久的
  持久 = 即使断电也保留数据
    （RAM 数据在断电时丢失）
  多种“磁盘”：
    硬盘（大但慢，便宜）
    固态硬盘（更小，但速度更快，而且更昂贵）
  通用接口：扇区数组，通常为 512 字节

硬盘驱动器 (HDD)
  磁盘以恒定速率旋转（例如 7200 RPM）
  同心轨道
  每个磁道都是一系列扇区
  读/写块：
    求头部走上正轨
    等待扇区在头部下方旋转
    随机访问很慢（5 或 10 毫秒，由于查找+旋转）
    顺序访问速度更快（100 MB/秒）
      b/c 位在磁盘上非常密集
  每个扇区的 ECC（Reed-Solomon，几百位）
  只能读/写整个扇区
  因此：子扇区写入很慢（读取-修改-写入）

固态硬盘 (SSD)
  非易失性“闪存”存储器
  随机访问：100微秒
  顺序：500 MB/秒
  内部复杂——除了有时表现之外是隐藏的
    在重写闪存之前，必须以大块的形式擦除闪存
    限制闪存块可写入的次数
    SSD 维护内部间接级别——重新映射块

对于 HDD 和 SSD：
  接口兼容——块数组
  顺序访问的吞吐量比随机访问高得多
  大读/写比小读/写快
  这些都会影响 FS 的设计和性能
  
块大小
  大多数操作系统文件系统都使用大块，例如4 KB 块 = 8 个扇区
  减少簿记并寻求间接费用
  xv6 使用 1024 字节块（2 个扇区）

磁盘布局
  xv6 将磁盘视为块数组
  0：未使用
  1：超级块（大小，ninodes）
  2：交易日志（31 个区块）
  33：inode 数组，每个 64 字节，每块打包 16 个
  46：块正在使用的位图（0=空闲，1=已使用）
  47：文件/目录内容块...
  确切的数字取决于 # 个 inode、# 个块

“元数据”
  磁盘上除文件内容之外的所有内容
  超级块、索引节点、位图、目录内容

xv6 的 mkfs 程序为空文件系统生成此布局
  布局在文件系统的生命周期内是静态的
  mkfs 将内核需要的大小 &c 放入超级块中

超级块
  [kernel/fs.h]
  日志、索引节点、位图、内容区域的大小和位置
  内核在启动时读取此内容

磁盘上的索引节点
  [kernel/fs.h]
  类型（自由、文件、目录、设备）
  链接
  尺寸
  地址[12+1]

直接和间接块
  间接块可容纳 256 个块#
  所以最大文件大小为 12+256 块，或 268 KB

example:
  如何找到文件字节8000的磁盘块#？
  逻辑块 7 = 8000 / BSIZE (=1024)
  inode.addrs[7] 保存磁盘块 #

每个 i 节点都有一个 i 编号
  给定 i 编号，很容易在磁盘上找到 i 节点
  inode 长度为 64 字节
  磁盘上的字节地址：33*BSIZE + 64*inum

目录内容
  目录实现为 T_DIR 类型的索引节点
    与文件共享大量实现
  内容是 dients 数组
  dirent:
    [kernel/fs.h]
    伊努姆
    14字节文件名
  如果 inum 为零，则 dirent 是免费的
  应用程序可以读取目录来查找文件名
    应用程序不能直接写入目录

根目录 (/) 是 i-number 1，由 mkfs 创建
  所以 xv6 知道在哪里可以找到它

您应该将 FS 视为磁盘上的数据结构

xv6 磁盘布局在硬盘驱动器上性能较低

既然磁盘太慢，那么缓存怎么样？
  xv6 FS 缓存有两个级别：
    bio.c 中磁盘块的缓存
    fs.c 中活动 i 节点的缓存

我们看一下bio.c中的块缓存
   块缓存仅保存一些最近使用的块
   bcache 位于 bio.c 的开头

FS 调用 bread，bread 调用 bget
   bget 查看块是否已缓存
   如果存在，锁定（可能等待）并返回块
     可能会在睡眠锁中等待，直到当前使用的进程释放
     睡眠锁定使呼叫者进入睡眠状态（如果已锁定）
   如果不存在，则重新使用现有的缓冲区
   b->refcnt++ prevents buf from being recycled while we're waiting
   不变式：内存中磁盘块的一份副本

这里有两个级别的锁定
  bcache.lock 保护缓存中内容的描述
  b->lock protects just the one buffer
