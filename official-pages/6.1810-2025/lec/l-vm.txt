* 页表提供一定程度的间接寻址
  CPU -> MMU -> RAM
      VAPA
  软件只能 ld/st 到虚拟地址，而不是物理地址
  内核告诉MMU如何将每个虚拟地址映射到物理地址
    MMU 本质上有一个表，由 va 索引，产生 pa
    称为“页表”
    弗吉尼亚州 |帕
    -------
    x| y
  代码只能使用表中具有映射的地址

* 我们希望每个进程有不同的地址空间
  所以我们需要多个页表——并且需要切换
  MMU 有一个寄存器（satp），内核写入该寄存器来更改页表

* 页表位于哪里？
  记忆中
  satp 保存当前页表的（物理）地址
  MMU从内存加载页表条目
  内核可以通过将页表写入内存来修改页表

* 页表有多大？
  可能有 2^64 个不同的虚拟地址
  拥有一个包含 2^64 个条目的表是不切实际的！
  许多细节都是为了减小尺寸

* RISC-V 映射 4 KB“页面”
  页表只需每页有一个条目
  4 KB = 12 位
  RISC-V有64位地址，因此最多52位页地址
    64 位地址 - 12 位页偏移 = 52 位页索引
  条目仍然太多，因此硬件通常会做出进一步的假设
    RISC-V Sv39 将地址空间限制为 512GB（39 位）
    27位页表索引
    如果应用程序需要超过 512GB，则需要更改硬件（Sv48、Sv57）

* 为什么树形页表节省空间？

* 为什么是 9 位？
  9位决定了页目录的大小
  9 bits -> 512 PTEs -> 64 bits / PTE -> 4096 bytes, or one page
  也就是说，9 位意味着一个目录适合一页

* 即使发生在硬件中，遍历树不是很昂贵吗？
  是的，CPU 的 MMU 通常会缓存最近使用的翻译
  该缓存称为转换后备缓冲区 (TLB)
  使TLB更有效：页表支持超级页
  内核知道 TLB，使用 sfence.vma 刷新它

* PTE 中的标志
  V、R、W、X、U

* 如果 V 位未设置怎么办？或者当 W 位未设置时发生存储？

    access -> page fault -> allocate memory -> install PTE -> resume process
  页面错误可能是由于应用程序错误造成的：xv6 内核打印错误，终止进程
    “usertrap()：意外原因...pid=...sepc=...stval=...”
  使用页表可以实现许多其他技巧
    例如，在 L4 中传递页面而不进行复制
