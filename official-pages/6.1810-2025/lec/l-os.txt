无操作系统的主要问题：缺乏隔离
  资源隔离：
    一个应用程序使用过多内存，或占用 CPU，或使用所有磁盘空间
  内存隔离：
    一个应用程序的错误写入另一个应用程序的内存

Unix 系统调用接口以有助于隔离的方式限制应用程序
  通常通过抽象硬件资源
  fork() 并处理抽象核心
    操作系统在进程之间透明地切换核心
    强制进程放弃它们
    可以拥有比核心更多的进程
  exec()/sbrk() 和虚拟地址抽象 RAM
    每个进程都有自己的内存——地址空间
    操作系统决定应用程序在内存中的放置位置
    操作系统限制进程使用自己的内存
  文件抽象磁盘级块
    操作系统确保不同用途不会冲突
    操作系统强制执行权限
  管道抽象内存共享

隔离既涉及安全性，也涉及错误
 
操作系统设计者对安全性有何假设？
  我们假设用户代码是主动恶意的
    积极尝试打破孤立
    积极尝试欺骗系统调用来做一些愚蠢的事情
    积极尝试干扰其他程序
  我们假设内核代码是可信的
    我们假设内核开发人员是善意且有能力的
    我们不太担心内核代码滥用其他内核代码。
    当然，内核中仍然存在错误
  因此内核必须仔细对待所有用户交互
  => Requires a security mindset
    内核中的任何错误都可能是安全漏洞
  [从安全角度来说，内核位于可信计算库（TCB）中]

硬件级隔离
  CPU 和内核是共同设计的
  - 用户/管理员模式
  - 虚拟内存
  
用户/管理员模式（也称为内核模式）
  管理模式：可以执行“特权”指令
    例如，设备硬件访问
    例如，修改页表
  用户模式：无法执行特权指令
  内核处于管理模式，应用程序处于用户模式
  [RISC-V还有M模式，我们大多忽略]

处理器提供虚拟内存
  page table maps VA -> PA
  限制用户进程可以使用的内存
  操作系统设置页表，以便每个应用程序只能访问其内存
    并且无法获取内核内存
  页表只能在超级用户模式下更改
  我们将花费大量时间研究虚拟内存......

让我们特别看看 xv6

xv6 仅在 RISC-V CPU 上运行
  并需要对周围设备进行特定设置——主板
  以“SiFive HiFive Unleashed”板为模型
  hifive.pdf
  一个简单的板（例如，没有显示器）
    - 4核RISC-V处理器
    - 内存 (128 MB)
    - 用于控制台的 UART
    - 类似磁盘的存储
    - 以太网
    - 像这样的板很便宜，但功能不强
  Qemu 模拟该 CPU 和一组类似的板设备
    - 称为“virt”，如“qemu -machine virt”
      https://github.com/riscv/riscv-qemu/wiki
    - 靠近 SiFive 板 (https://www.si Five.com/boards)
      但使用 virtio 作为磁盘

这块板上的 RISC-V 芯片内部有什么？
  四个核心，每个核心有
    32个寄存器
    ALU（加、乘、&c）
    内存管理单元
    控制寄存器
    定时器、中断逻辑
    总线接口
  核心在很大程度上是独立的，例如每个都有自己的寄存器
    他们共享内存
    他们共享主板设备
