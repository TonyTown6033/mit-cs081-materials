xv6如何使用线程？
  [简单图]
  每个 xv6 进程都有一个用户级线程，
    和单个内核线程
  进程的内核线程执行系统调用实现
    并且可能必须暂停自身以等待输入&c
    或让其他进程的线程运行
  xv6 内核线程共享内存——它们都执行
    在内核地址空间中，它们都使用内核数据结构，
    因此他们需要锁定
  进程的用户线程和内核线程不是独立的！
    如果在内核中执行，用户线程正在等待陷阱返回
    如果在用户空间执行，则没有执行的内核线程
  本讲座将互换使用“进程”和“线程”

如果 xv6 进程未执行
  它经常等待一些事件——控制台、管道、磁盘等
    因为它对内核进行了系统调用，例如读()
    将在下一讲中深入探讨这方面
  可能在复杂的内核系统调用实现过程中等待
    需要在内核系统调用代码中从中断处恢复
    因此必须保存其内核寄存器（和堆栈）

xv6 进程/线程保存状态
  用户记忆
  用户保存的寄存器（在陷阱帧（TF）中）
  内核堆栈
  内核保存的寄存器（“上下文”（CTX））
  kernel p->state

p->state tells the scheduler how to handle the process
  RUNNING —— 立即在 CPU 上执行（在用户或内核中）
  RUNNABLE——想要执行，但没有执行（在内核中挂起）
  SLEEPING——等待事件（挂起，在内核 read()、wait() 等中）
  有助于避免同时在两个 CPU 上执行等错误

xv6 如何从一个进程切换到另一个进程——“上下文切换”
  例如P1 调用等待的 read()，P2 处于 RUNNABLE 状态
  [P1、TF1、KSTACK1、CTX1、swtch()、
   CTX、堆栈、swtch()、
   CTX2、KSTACK2、TF2、P2]
  TF = trapframe = 保存的用户寄存器
  CTX = 上下文 = 保存的内核寄存器
  从一个用户进程到另一个用户进程涉及多次转换：
    user -> kernel; saves user registers in trapframe
    kernel thread -> scheduler thread; saves kernel thread registers in context
    scheduler thread -> kernel thread; restores kernel thread registers from ctx
    kernel -> user; restores user registers from trapframe

proc.h 中的结构体 proc
  p->trapframe holds saved user thread's registers
  p->context holds saved kernel thread's registers
  p->kstack points to the thread's kernel stack
  p->state is RUNNING, RUNNABLE, SLEEPING, &c
  p->lock protects p->state, which cpu is running p, and other things

proc.c 中的 proc[NPROC] 数组——每个进程一个

为什么需要一个单独的调度程序线程？
  这样总有一个堆栈可以运行调度程序循环
  例如从现有进程切换
  例如进程数少于 CPU

调度程序线程详细信息
  每个 CPU 一个；每个都有一个堆栈和一个结构体上下文
  内核线程总是切换到该CPU的调度程序线程
    如果一个内核线程处于可运行状态，则切换到另一个内核线程
    从来没有直接的进程到进程切换
  每个CPU的调度线程不断扫描proc[]进程表
    直到找到一个 RUNNABLE 线程
  如果没有 RUNNABLE 线程，则调度程序处于“空闲”状态

Q: why hold p->lock across swtch()?

p->lock prevents interference during these steps:
  * p->state=RUNNABLE
  * save registers in p->context
  * 停止使用p的内核堆栈
  因此，在所有步骤完成之前，另一个 CPU 的调度程序不会开始运行 p

   P2 持有 L2，因此当 P2 在 acquire(L1) 中旋转时中断关闭
     -> timer interrupts won't occur
     -> P2 won't yield the CPU
